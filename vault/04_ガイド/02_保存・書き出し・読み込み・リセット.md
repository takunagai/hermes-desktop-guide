## 保存方式

| 対象 | 保存方法 | 反映 |
|---|---|---|
| チャット、ワークスペース、安全性、メモリ、音声、詳細 | 変更後約 550 ms で自動保存 | 保存後 |
| 言語 | 選択後に設定へ保存 | 保存完了後 |
| 外観のモード・テーマ・ツール表示 | デスクトップのローカル UI 設定 | 即時 |
| メインモデル | 「適用」 | 新規セッション。進行中はピッカーで変更 |
| プロバイダー・ツール認証情報 | 各カードの「設定」「置き換え」 | 保存・再読み込み後 |
| ゲートウェイ | 「次回起動時のために保存」または「保存して再接続」 | ボタンに応じる |
| MCP | 「サーバーを保存」後に「MCP を再読み込み」 | 新しいターン |
| デフォルトプロジェクトディレクトリ | フォルダーピッカーで選択 | 新規セッション |

## 設定ナビ下部の3操作

設定の書き出し・読み込み・デフォルトに戻すの3操作は、設定画面左側のナビゲーション下部（フッター）に、3つのアイコンボタン（下向き矢印・上向き矢印・円形矢印）として並ぶ。ポインターを載せると「設定を書き出す」「設定を読み込む」「デフォルトに戻す」のラベルが表示される。

### 設定を書き出す

現在の Hermes 設定を `hermes-config.json` としてダウンロードする。更新前、大幅変更前、別端末へ移す前に実行する。

> [!warning] 認証情報は別管理
> 書き出し JSON と API キー・OAuth セッション・デスクトップのローカル表示設定は、同じ範囲とは限らない。復元時は個別に確認する。

### 設定を読み込む

JSON ファイルを選択すると設定として読み込まれ、自動保存される。現在の設定と互換性があるか、特に以下を確認する。

- モデルとプロバイダー名
- 作業ディレクトリ
- 実行バックエンド
- プライベート URL 設定
- MCP サーバー
- 更新時のローカル変更処理

### デフォルトに戻す

確認ダイアログの後、このビルドの製品既定値を保存する。実行前に書き出す。プロバイダー認証や外観のローカル保存がすべて同時に消えるとは限らない。

## セッションデータの書き出しと整理（CLI）

設定とは別に、セッション履歴（チャットの記録）は SQLite のセッションストアに保存される。`hermes sessions export` は単一コマンドで複数形式に書き出せ、`prune` のフィルターと `archive` を使って整理できる。

前提: ターミナルで `hermes` コマンドが実行できること。オプションの全容は `hermes sessions export --help` で確認できる。

### 書き出し形式（--format）

| 形式 | 出力 | 主な用途 |
|---|---|---|
| `jsonl`（既定） | JSONL ファイル。出力パス必須（`-` で標準出力） | 機械処理・バックアップ |
| `md` | セッションごとの Markdown ＋ `manifest.jsonl` | 閲読・ナレッジ化 |
| `qmd` | Quarto Markdown ＋ `manifest.jsonl` | Quarto での文書化 |
| `html` | メッセージをすべて埋め込んだ自己完結の単一 HTML ファイル。複数セッションはサイドバー付きの 1 ファイル | ブラウザ閲覧・共有 |
| `trace` | Claude Code 形式 JSONL（Hugging Face Agent Trace Viewer 用） | トレース解析・データセット化 |

- `md` / `qmd` の既定の出力先は Hermes ホームの `session-exports/`。書き出しのたびに出力先の `manifest.jsonl` へ 1 行追記され、各ファイルの SHA-256 ハッシュが記録される。
- `html` は出力ファイルパスの指定が必須。
- `trace` は既定で秘密情報のリダクト（伏せ字化）が強制される。`--no-redact` は内容を目視確認した後にだけ使う。
- `trace` に `--upload` を付けると、ローカルファイルの代わりに Hugging Face の私設データセット `hermes-traces` へアップロードする（`HF_TOKEN` が必要。公開データセットにする場合のみ `--public`）。

成功すると `Exported ...` の行が出力される。失敗時はコマンドの出力メッセージ（形式ごとの必須引数や `--force` の案内が表示される）を確認する。

### 主なオプション

| オプション | 対象形式 | 動作 |
|---|---|---|
| `--only user-prompts` | `jsonl` / `md` | ユーザープロンプトだけを抽出して書き出す |
| `--redact` | `jsonl` / `md` / `qmd` / `html` | API キー・トークン等の秘密情報を伏せて書き出す（オプトイン）。`trace` は既定でリダクトが強制されるため `--redact` は効かない（無効化は `--no-redact`） |
| `--lineage logical` | `md` / `qmd` | コンパクション（圧縮）で分かれた前身セッションの系譜を 1 つの論理セッションとして書き出す |
| `--delete-after-verified` | `md` / `qmd` | 書き出しファイルの検証成功後に元セッションを削除する。`--session-id` と `--yes` の同時指定が必須 |
| `--session-id` | 全形式 | セッション ID（一意な前方一致可）で対象を 1 件に絞る |

対象の絞り込みには、経過時間（`--older-than` / `--newer-than` / `--before` / `--after`）、プラットフォーム（`--source`）、作業ディレクトリ（`--cwd`）などのフィルターを組み合わせられる（一覧は次の prune と共通）。`--dry-run` を付けると、書き出さずに対象セッションだけを確認できる。

### sessions prune ─ フィルター付き一括削除

`hermes sessions prune` は古いセッションを削除する。

| 分類 | フィルター |
|---|---|
| 時間 | `--older-than` / `--newer-than` / `--before` / `--after` |
| 属性 | `--source` / `--title` / `--end-reason` / `--cwd` / `--model` / `--provider` / `--user` / `--chat-id` / `--chat-type` / `--branch` |
| 数値 | `--min-messages` / `--max-messages`、`--min-tokens` / `--max-tokens`、`--min-cost` / `--max-cost`、`--min-tool-calls` / `--max-tool-calls` |
| 安全確認 | `--dry-run`（一覧表示のみ）/ `--yes`（確認スキップ） |

> [!caution] 暗黙の 90 日既定
> フィルターなしの `hermes sessions prune` は「90 日より古いセッション」を対象とする。フィルターを 1 つでも指定すると、この 90 日既定は無効になり全期間がマッチ対象になる。実行前に必ず `--dry-run` で対象を確認する。

アーカイブ済みセッションは既定で削除対象から除外される（含めるには `--include-archived`）。

### sessions archive ─ 削除しない整理

`hermes sessions archive` は、フィルターに一致するセッションを一括アーカイブ（ソフト非表示）する。削除はしないため、「消すほどではないが一覧から片付けたい」セッションの整理に向く。フィルターと `--dry-run` / `--yes` は prune と共通。アーカイブしたセッションの確認・復元は [[03_設定/13_アーカイブ済みチャット|アーカイブ済みチャット]] から行える。

### 再開時の作業ディレクトリ復元と一覧の絞り込み

CLI でセッションを再開すると、そのセッションに記録された作業ディレクトリへ自動で戻ってから再開する（`--no-restore-cwd` で無効化。ディレクトリが消えている場合は警告して現在地に留まる）。また `hermes sessions list --workspace <名前>` で、特定のリポジトリ・プロジェクトディレクトリのセッションだけを一覧できる。

## 推奨バックアップ手順

1. 「設定を書き出す」で JSON を保存する。
2. MCP のサーバー JSON を確認する。
3. 使用中のプロバイダー名だけを控える。キー値は記録しない。
4. [[03_設定/14_情報|情報]] のバージョンとコミットを記録する。
5. セッション履歴も残す場合は `hermes sessions export` を併用する。
6. 復元後は安全性、作業ディレクトリ、ゲートウェイを最初に確認する。
