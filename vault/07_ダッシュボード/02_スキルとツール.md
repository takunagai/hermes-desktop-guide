> [!note] 確認状況
> 画面構成（4タブ化・MCPタブ・一括操作）と「v0.19 での既知の差分」の内容は、v0.19 実機ソース（コミット `967e078a`）で確認した。一方、本文のツールセット全 26 件・スキル 103 件（19 カテゴリ）の一覧表は v0.17 実機（ビルド `857d024`、2026-06-20 確認）時点のスナップショットのままで、v0.19 実機の GUI では再監査できていない（このため status: needs-review）。件数・カテゴリ・有効数、「設定済み」/「キーが必要」表示は、導入したスキルや API キーの設定状況によって変わる。

左ナビの「スキルとツール」は、「新しいセッション」「メッセージング」「アーティファクト」と並ぶトップレベル画面。v0.19 で、スキル・ツールセット・MCP・スキルハブを 1 か所に統合した「Capabilities」ページ基盤に刷新された（PR #57590・#57441・#67482）。エージェントが使える**スキル**と**ツールセット**の有効 / 無効に加えて、MCP サーバーの管理とスキルハブからのスキル導入までこの画面で完結する。リリースノートは、スキルハブ・MCP のテスト / トグル / カタログ・メンテナンス操作・ログフィルターについて、CLI・Web ダッシュボードとの機能パリティを掲げている。

## 画面構成（v0.19）

上部のタブは次の 4 つ。ウィンドウ幅が狭いときは、タブ列が自動的にドロップダウンへ畳まれる。

| タブ | 内容 |
|---|---|
| スキル | 導入済みスキルの一覧と有効 / 無効の切り替え。カテゴリは各行のサブタイトルとして表示され、検索は名前・説明・カテゴリ名に一致する |
| ツールセット | 組み込みツールセットの一覧と有効 / 無効の切り替え。タブラベル脇には表示対象ツールセットの総数が表示される（有効数 / 総数の集計は表示されない） |
| MCP | MCP サーバーの追加・編集、接続テスト、ツール単位の有効 / 無効、OAuth 認証、カタログからの導入、ログの確認。管理の詳細は [[03_設定/12_MCP|MCP]] を参照 |
| Browse Hub | スキルハブ。公式インデックス・GitHub・コミュニティのスキルを横断検索し、プレビュー・セキュリティスキャン・導入・更新・削除を行う |

- MCP 管理は設定画面からこの画面の MCP タブ（内部ルート `/skills?tab=mcp`）へ移動した。旧「設定 → MCP」のリンクやブックマークを開くと、自動的にこの画面の MCP タブへ移る。
- 「Browse Hub」タブは確認時点で日本語訳が未収録のため、日本語 UI でも英語ラベルのまま表示される。
- 検索ボックスはスキル・ツールセット・ハブの各タブで使える。MCP タブには表示されない（対象が少なく、編集画面がその場にあるため）。

スキル・ツールセットのタブでは、トグルによる個別切り替えに加えて次の操作ができる。

- ソート切り替え ─ 「↓ 使用頻度順」と「↑ 使用頻度が低い順」。使用実績は各行に「N 回使用」と表示される。
- 一括操作 ─ 「すべて有効化」「すべて無効化」と、使用実績のないスキルをまとめて切る「未使用を無効化」。
- 由来バッジ ─ 標準以外の出どころを持つスキルの行に、学習済み（行の表示は英語で `learned`）・ハブ（同 `hub`）のバッジが付く。組み込みスキルにはバッジが付かない。日本語ラベル（学習済み / 組み込み / ハブ）が出るのは詳細ペインのピルで、これも組み込み以外にだけ表示される。
- SKILL.md のアプリ内編集とアーカイブ ─ 編集・アーカイブの対象は学習済み（ローカル生成）スキルのみで、組み込み・ハブ由来のスキルはアプリ内で編集・アーカイブできない。アーカイブしたスキルは `hermes curator restore` で復元できる。

変更はいずれも新しいセッションから適用される。

> [!tip] スキルとツールセットの違い
> - **ツールセット**は、エージェントが直接呼び出す組み込みツール（関数）をまとめた単位。`web_search` や `read_file` のような具体的な操作で、含まれるツール名（タグ）が各行に表示される。
> - **スキル**は、特定の作業手順やノウハウを記述した拡張（SKILL.md）。有効にすると、その手順をエージェントが必要に応じて参照・実行できる。`apple-notes` や `github-pr-workflow` のように、外部 CLI やサービスの使い方をまとめたものが多い。
>
> どちらもトグルが ON のものだけがエージェントから使える。

> [!note] 「設定済み」と「キーが必要」
> 各行の状態バッジは、そのツールセットを有効化できる状態かどうかを示す。**設定済み**は追加設定なしで（または必要なキーが既に揃っていて）ON にできる状態。**キーが必要**は、対応する API キー等を設定するまで有効化できない状態で、実機例では Home Assistant と Mixture of Agents が該当した。X (Twitter) Search のようにキーが要るツールセットでも、キー設定済みなら「設定済み」と表示される。つまりバッジは環境のキー設定状況で変わり、トグルの ON / OFF（実機例では 7 件が OFF）とは別物。

主なカテゴリの傾向は次のとおり。

- **Apple / Smart-Home / Media**: macOS のメモ・リマインダー・iMessage・FindMy、Philips Hue、Spotify や YouTube など、手元の端末・サービスを操作するスキル。
- **Autonomous-AI-Agents**: `claude-code`・`codex`・`opencode` など、別のコーディングエージェントへ実装を委譲するスキル群。
- **General / Github / Software-Development**: Cloudflare 開発（Workers・D1・R2・Durable Objects）、GitHub の PR / Issue 運用、計画立て（`plan`・`writing-plans`）・TDD・体系的デバッグなど、開発作業の手順。
- **Creative**: 図版・ASCII アート・インフォグラフィック・作曲・p5.js など、制作物を作るスキル。
- **Mlops**: vLLM や llama.cpp によるモデル提供、評価、HuggingFace 連携などの ML 運用。

> [!tip] スキルとは
> スキルは特定の作業手順やツール群をまとめた拡張。有効にしたスキルだけがエージェントから参照・実行できる。使う予定のないスキルは OFF にしておくと、意図しない動作や候補の混在を避けられる。

> [!caution] 安全性に関わるスキル
> 一覧には、Red-Teaming カテゴリの `godmode`（LLM のジェイルブレイク手法）や Mlops の `obliteratus`（モデルの拒否応答を除去する手法）など、LLM の安全機構を回避する目的のスキルも含まれうる。v0.19 のリポジトリでは、この 2 つは既定では導入されないオプションスキルへ移されているが、導入済みの環境では引き続き一覧に表示される。有効化しただけで自動実行されるわけではないが、意図せず使われないよう、必要なスキルだけを ON にし、用途が不明なものは OFF のままにしておく。

## v0.19 での既知の差分

上の一覧（v0.17 実機時点）に対して、v0.19 のソース（コミット `967e078a`）で確認できた差分は次のとおり。

前提として、同梱スキルはリポジトリ側で 2 系統に整理されている。セットアップ時に既定で導入される `skills/` と、既定では導入されない公式オプションスキル `optional-skills/` で、オプションスキルはスキルハブ（この画面の Browse Hub タブ、または `hermes skills browse --source official`）から探して導入すると一覧に加わる。

- **computer-use への再編** ─ Apple カテゴリの `macos-computer-use` は廃止され、クロスプラットフォーム対応の `computer-use`（macOS・Windows・Linux、v2.0.0）として独立カテゴリに再編された。ツールセット名も「Computer Use (macOS)」から「Computer Use (macOS/Windows/Linux)」に変わっている。
- **新スキル**（PR #57438・#57902・#64715・#65066）
  - `unbroker`（security・オプション）─ データブローカーサイトに載った自分の情報を自律的に削除する。
  - `unreal-mcp`（creative・オプション）─ Unreal Engine 公式のエディタ組み込み MCP サーバー（カタログエントリ `unreal-engine`）でシーン構築やエディタ自動化を行う。
  - `mcp-oauth-remote-gateway`（mcp・オプション）─ ヘッドレスなゲートウェイ環境でリモート MCP サーバーの OAuth 認証を手動で通す。
- **更新されたスキル** ─ `blender-mcp` は MCP カタログの `blender` エントリと連携する構成に刷新された（v2.1.0）。`humanizer` は検出パターンが拡張された。
- **skills install の同梱範囲** ─ URL・GitHub からのスキルインストールは SKILL.md 単体ではなく、`references/`・`templates/`・`scripts/`・`assets/`・`examples/` に置かれた参照ファイルも併せて取り込む（URL 指定では SKILL.md から明示参照されたファイルのみ取得する）。
- **スラッシュコマンドでのスタック起動** ─ 導入済みスキルは CLI・TUI で `/skill-a /skill-b やること` のように先頭へ並べた最大 5 個を順に読み込むスタック起動に対応した。詳細は [[06_リファレンス/05_スラッシュコマンド一覧|スラッシュコマンド一覧]] を参照。

## 前提・操作・確認

- 前提: 「スキルとツール」画面が開け、スキル・ツールセット・MCP・ハブの各タブが表示されること。
- 操作: 使いたいスキル・ツールセットのトグルを ON にする。「キーが必要」のものは先にキーを設定する。MCP サーバーの追加・接続テストは MCP タブで行う。
- 期待結果: 有効にしたスキル・ツールセット・MCP ツールが、新しいセッションからエージェントで使える。
- 使えないとき: トグルが ON か、「キーが必要」表示が残っていないか、対象の API キー設定を確認する（[[03_設定/11_ツールとキー|ツールとキー]]・[[03_設定/12_MCP|MCP]]）。
