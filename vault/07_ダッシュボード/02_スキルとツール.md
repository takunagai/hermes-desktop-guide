## 画面構成

上部のタブは次の 4 つ。ウィンドウ幅が狭いときは、タブ列が自動的にドロップダウンへ畳まれる。Plugins と Connectors はタブ名が英語のまま（日本語リソース未整備のため英語表示）。Connectors は本文の大半も英語表示。

| タブ | 内容 |
|---|---|
| スキル | スキルのカタログ。導入済みスキルの有効 / 無効の切り替えと、カタログからのスキル導入を 1 つの画面で行う。タブラベル脇には対象スキルの総数（実機例では 74）が表示される（後述） |
| Plugins | プラグインのカタログ。エージェントプラグインとデスクトッププラグインのインストール・有効化・更新・削除、自動更新の切り替え（後述） |
| Connectors | Nous がホストするアプリと、このデバイスで動く MCP サーバーを 1 つの一覧で管理する。MCP サーバーの追加もここから行う（後述） |
| ツールセット | 組み込みツールセットのカードと有効 / 無効の切り替え。タブラベル脇には表示対象ツールセットの総数（実機例では 23）が表示される（有効数 / 総数の集計は表示されない） |

- **スコープ選択** ─ タブ列の下に「Configuring:」（英語表示）のセレクタがあり、どのプロファイル・どの接続先（このデバイス / 保存済みのゲートウェイ）の設定を編集しているかを切り替えられる。
- **MCP の場所** ─ MCP サーバーの管理は独立したタブや設定画面ではなく、Connectors タブの中にある。旧「設定 → MCP」や旧 MCP タブへのリンクを開くと、自動的に Connectors タブへ移る（内部ルート `/capabilities?tab=connectors`）。
- **検索** ─ スキル・Plugins・ツールセットの各タブには上部に検索ボックスがある（スキルは「「general」を試す」、Plugins は「プラグインを検索」のようなプレースホルダー）。Connectors タブは一覧の上に専用の検索欄（「Search N apps」）を持つ。

### カタログ表示（スキル・Plugins タブ）

スキルタブと Plugins タブは、同じ形のカタログ画面になっている。導入済みの項目とカタログの項目が 1 つの一覧に並び、スキルハブやプラグインカタログを別の画面で開く必要はない。

- **絞り込み** ─ 検索欄の下に切り替え（スキルは「カテゴリ」「提供元」、Plugins は「カテゴリ」「Tier」）と、「すべて」から始まるチップ（`Account Management`、`Automation` など。英語表示）が並ぶ。右端の「フィルター」でさらに絞り込める。
- **一覧と詳細** ─ 左に一覧、右に選んだ項目の詳細が出る。一覧の各行は名前・英語の説明・タグ・提供元・バッジ（スキルは `Built In` など、プラグインは Tier）・版数。詳細には「リポジトリ」「ドキュメント」のリンク、対応プラットフォーム、追加日、レビュー済みコミット、「類似の項目」が出る。
- **導入** ─ まだ入っていない項目は、詳細右上の「+ インストール」（一覧のカードでは「+」）で入れる。カードの「+」はインストールするだけで、削除はインストール後の詳細から行う。詳細の下には「インストール前にソースを確認してください。変更は新しいセッションに適用されます。」と表示される。
- 画面下部の注記「Hermesカタログの情報です。閲覧時に提供元のリポジトリへ接続することはありません。」のとおり、カタログの情報は Hermes が配る写しで、閲覧だけでは提供元に接続しない。

### スキルタブの操作

導入済みスキルにはスイッチが付き、個別に有効 / 無効を切り替えられる。加えて次の操作ができる（ソースで確認）。

- 一括操作 ─ タブのメニューから全スキルの一括オン / オフ（検索や絞り込みの結果ではなく、プロファイルの全スキルが対象）と、使用実績のないスキルをまとめて切る「未使用を無効化」。導入済みスキルの一括更新ボタンもある。
- 使用実績 ─ 使ったことのあるスキルは、詳細に使用回数が表示される。
- ロック ─ スキル詳細の「ロック」を押すと「ロック中」になり、エージェント（キュレーター）がそのスキルを書き換えられなくなる。説明文は「ロック中はエージェントがこのスキルを変更できません。自分では引き続き編集できます。」。ロック中のスキルは一覧の行にも鍵アイコンが付く。CLI では `hermes curator lock`。
- SKILL.md のアプリ内編集とアーカイブ ─ 編集・アーカイブの対象は学習済み（ローカル生成）スキルのみで、組み込み・ハブ由来のスキルはアプリ内で編集・アーカイブできない。アーカイブしたスキルは `hermes curator restore` で復元できる。

変更はいずれも新しいセッションから適用される。

> [!tip] スキルとツールセットの違い
> - **ツールセット**は、エージェントが直接呼び出す組み込みツール（関数）をまとめた単位。`web_search` や `read_file` のような具体的な操作で、含まれるツール名（タグ）が各行に表示される。
> - **スキル**は、特定の作業手順やノウハウを記述した拡張（SKILL.md）。有効にすると、その手順をエージェントが必要に応じて参照・実行できる。`apple-notes` や `github-pr-workflow` のように、外部 CLI やサービスの使い方をまとめたものが多い。
>
> どちらもトグルが ON のものだけがエージェントから使える。

> [!tip] スキルとは
> スキルは特定の作業手順やツール群をまとめた拡張。有効にしたスキルだけがエージェントから参照・実行できる。使う予定のないスキルは OFF にしておくと、意図しない動作や候補の混在を避けられる。

> [!caution] 安全性に関わるスキル
> `godmode`（LLM のジェイルブレイク手法）や `obliteratus`（モデルの拒否応答を除去する手法）のような、LLM の安全機構を回避するスキルは、同梱スキルには含まれない。オプションスキル（`optional-skills/`）へ移されており、カタログから明示的にインストールしたときだけ導入済みスキルに加わる。有効化しただけで自動実行されるわけではないが、意図せず使われないよう、必要なスキルだけを ON にし、用途が不明なものは OFF のままにしておく。

### ツールセットの設定パネル

カードを選ぶと、そのツールセットの設定パネルが開く（以下はソースと前回の実機確認に基づく。カード表示での開き方は実機未確認）。

- **選ぶだけでは切り替わらない**。パネルを開いても、そこにあるバックエンドやプロバイダーが選ばれるわけではない。
- バックエンドを切り替えるときは、パネル内の「**このバックエンドを使う**」ボタンを明示的に押す（Terminal & Processes ツールセットの「実行バックエンド」パネルなど。ボタン文言はソース由来で、Local 使用中の実機ではボタンが表示されないため未確認）。
- 「実行バックエンド」パネルには Local / Docker / Modal / Daytona / SSH の行が並び、使用中の行に「準備完了」「使用中」、未設定の行に「セットアップが必要」と英語の警告文（Docker に接続できない、Modal の資格情報が無い、`DAYTONA_API_KEY` 未設定、`terminal.ssh_host` / `terminal.ssh_user` 未設定など）が表示される。Singularity / Apptainer はコアから外れてプラグインになったため、そのプラグインが入っている環境でだけ、プラグインが返す状態とともに行が加わる（ソースで確認。以前 Singularity を使っていた環境にはプラグインが自動でインストールされる）。右下の注記は「変更は新しいセッションに適用されます。」。各バックエンドの意味は [[03_設定/08_詳細|詳細]] の「ターミナルのバックエンド」を参照。
- 現在使われているプロバイダーの行には「**使用中**」バッジが付く（内部キー `cfg.active_provider` / `provider.is_active`）。
- API キーなどの環境変数のフィールドでは、右クリックのコンテキストメニューが使える。
- ツールセットの有効・無効を切り替えるボタンのラベルは、現在の状態に応じて「〜をオンにする」「〜をオフにする」と変わる。

> [!note] 「設定済み」と「キーが必要」
> 各行の状態バッジは、そのツールセットを有効化できる状態かどうかを示す。**設定済み**は追加設定なしで（または必要なキーが既に揃っていて）ON にできる状態。**キーが必要**は、対応する API キー等を設定するまで有効化できない状態で、X (Twitter) Search のように外部サービスのキーや認証を前提とするツールセットが該当しうる。キー設定済みなら「設定済み」と表示される。つまりバッジは環境のキー設定状況で変わり、トグルの ON / OFF とは別物。

## Connectors

Connectors タブは、エージェントが使える外部アプリの接続先を 1 つの一覧で扱う。Nous がホストするアプリ（Managed）と、このデバイスで動く MCP サーバーが同じ一覧に並ぶ。タブの見出し・ボタン・カードの文言はすべて英語表示（日本語リソース未整備のため）。

![スキルとツール > Connectors 画面](@screenshots/skills-connectors.webp)

| 要素 | 内容 |
|---|---|
| Add your own | 右上のボタン。自分の MCP サーバーを追加するダイアログ「Connect to a custom MCP」を開く |
| 検索欄 | 「Search N apps」。アプリ名・説明で絞り込む |
| フィルタ | 件数付きのセグメント。実機では「All」「On this device」「Available」の 3 つ。ソースには接続済みの「Connected」とオフにした「Turned off」の区分も定義されている（該当するアプリがある環境での表示は未確認） |
| On this device | このデバイスの設定に登録されたローカル MCP サーバー。カードのスイッチで On / Off を切り替える |
| Available | まだ接続していないアプリ。カードの「Connect」（ホスト型アプリ）または「Install」（カタログの MCP サーバー）で接続・導入する |

カードの種別バッジは次のとおり。

| バッジ | 意味 |
|---|---|
| Managed | Nous がホストするアプリ。使うには Nous へのサインインが必要（未サインインなら「Sign in to Nous to use managed apps.」と表示される） |
| MCP · Catalog | Hermes のカタログに載っている MCP サーバー。「Install」でこのデバイスに導入する |
| MCP · Custom | 自分で追加した MCP サーバー |
| MCP · Plugin | プラグインが追加した MCP サーバー |

自分の MCP サーバーを追加するときは「Add your own」を押し、ダイアログにコマンドや設定スニペット（例 `npx -y @modelcontextprotocol/server-filesystem /path/to/dir`）を貼り付けるか、Name・Type などの欄を手で埋める。サーバーの編集・ログ・接続テスト・ツール単位の有効 / 無効・OAuth 認証などの詳細は [[03_設定/12_MCP|MCP]] を参照。

ホスト型アプリをエージェントから呼び出す経路は、ツールセットの「Connections」が担う。

> [!note] MCP サーバーは遅延起動
> MCP サーバーは、fingerprint キー付きのディスクキャッシュを使った遅延起動で扱われる。セッションを開始した時点で登録済みの MCP サーバーが一斉に起動するわけではない。

## Plugins

Plugins タブは、プラグインのインストール・有効化・更新・削除を 1 か所で行う画面。プラグインには、エージェント側に機能を足す**エージェントプラグイン**（Agent）と、このアプリの画面に機能を足す**デスクトッププラグイン**（Desktop）があり、1 つのパッケージが両方を持つこともある。上部の説明文は「プラグインはこのアプリ、エージェント、または両方を拡張できます。それぞれに独立したスイッチがあります。」。

![スキルとツール > Plugins 画面](@screenshots/skills-plugins.webp)

| 要素 | 内容 |
|---|---|
| 自動更新 | 検索欄の右にあるスイッチ（既定はオフ）。オンにすると、ゲートウェイが更新を確認するたび（既定 24 時間ごと）にプラグインの更新を自動で適用する。更新されたコードは新しいセッションで読み込まれる。config では `plugins.auto_apply`（確認間隔は `plugins.auto_update_check_hours`） |
| すべて更新 | インストール済みのすべてのプラグインを確認し、確認の要らない更新をまとめて適用する。結果は「N 件更新、N 件は確認が必要、N 件失敗」のように通知される。CLI では `hermes plugins update` |
| Git からインストール | Git リポジトリの URL を指定してプラグインを入れる。右隣にフォルダーを開くボタンと再読み込み（再スキャン）ボタン |
| 絞り込み | 「カテゴリ」「Tier」の切り替えと、`Automation` `Desktop` `General` などのカテゴリチップ（英語表示） |
| Tier | カタログでの区分。`Official`（Nous の公式）/ `Verified`（連携先の提供元自身が作り、Nous が検証したもの）/ `Community`（コミュニティ製）を英語のまま表示する（日本語リソース未整備のため英語表示）。Git から入れたものは「未確認」 |
| 一覧と詳細 | 左にプラグインのカード（名前・英語の説明・カテゴリ・作者・Tier・版数）、右に選んだプラグインの詳細（「+ インストール」、リポジトリ・ドキュメント、追加日、レビュー済みコミット、類似の項目） |

インストール済みのプラグインは、詳細に次の操作が出る（ソースで確認）。

| 要素 | 内容 |
|---|---|
| Desktop のスイッチ | このアプリの画面パネルの有効 / 無効。全プロファイル共通 |
| Agent のスイッチ | スコープ選択で選んだプロファイルでの有効 / 無効 |
| 更新 | 新しい版があると「Update to x.y.z」が出る（英語表示） |
| 削除 | 「Uninstall」（英語表示）。カードの「+」はインストール専用で、削除は詳細からだけ行う |

- **同梱のデスクトッププラグイン** ─ ボット（既定オン）、カンバン（既定オフ）、Radio（既定オフ。オンにするとステータスバーに再生ウィジェットが出る）。ボットは[[07_ダッシュボード/04_ボット|ボット]]を参照。カンバンの Desktop スイッチは、ツールセットの Kanban も連動して切り替える。
- **言語パック** ─ プラグインカタログには UI の言語パック（`hermes-lang-ko`、`hermes-lang-it` など）もある。エージェントプラグインとして入れると表示言語の選択肢に加わるが、表示言語は自動では切り替わらない（ソースで確認）。

各プラグインが持つ設定ページは、設定画面の [[03_設定/18_プラグイン|プラグイン]] から開く。

### インストール済みプラグインに付く表示

以下は前回の実機確認とソースに基づく。カタログ表示になってからの各表示の位置（カードか詳細か）は実機未確認。

| 表示 | 意味 |
|---|---|
| Agent / Desktop / Agent + Desktop | 種別バッジ。そのパッケージがエージェント側・アプリ側・両方のどれを持つか |
| `bundled` / `on disk` | デスクトッププラグインの由来。`bundled` はアプリに同梱、`on disk` は `desktop-plugins` フォルダーに置かれたもの（手で置いたもの・エージェントが書いたものを含む） |
| `Official` / `Verified` / `Community` | カタログでの区分（Tier）。Nous の公式、連携先の提供元自身が作り Nous が検証したもの、コミュニティ製 |
| `pinned @ <SHA>` | 特定のコミットに固定して入れたもの。固定し直して再インストールするまで更新を受け付けない |
| `portable` | ほかのエージェントでも使える形式（スキルと MCP のまとめ）のパッケージ |
| `<サーバー名>: connected` など | プラグインが持つ MCP サーバーの接続状態（`app not running`、`MCP connection missing`、`version too old` など） |
| `failed` | デスクトッププラグインの読み込みに失敗した。説明欄に赤字でエラーが出る。壊れたプラグインは分離されるため、アプリ本体は落ちない |
| Install here | アプリ側は読み込まれているが、選択中のプロファイルにエージェント側が入っていない。押すとそのプロファイルに入れる |
| copying… / unavailable (remote backend) | アプリ側の取り込み待ち（再読み込みかアプリ再起動で解消）、またはリモートのバックエンドにあってこの端末では読めない状態（Git からインストールで Desktop を選ぶと取り込める） |

- **スイッチの反映タイミング** ─ Desktop のスイッチはその場で読み込み / 解除され、アプリの再起動は要らない。Desktop の選択はこの端末に保存され（`config.yaml` には書かれない）、再起動後も保持される。Agent のスイッチはゲートウェイを再起動してから効く（説明文「Take effect after a gateway restart.」）。
- **読み取り専用の項目** ─ 古いバックエンドが返す項目はスイッチを操作できず、「This backend predates key-addressed plugin toggles — update Hermes to manage it here.」と表示される。Hermes を更新すると操作できる。
- **更新** ─ 「Update to x.y.z」でカタログの現在のピンに更新する。新しい版が追加の機能や権限を求める場合は「（名前） asks for more」の確認が出て、内容を見てから「Apply update」で適用する。更新後はゲートウェイの再起動で反映される。
- **削除** ─ エージェントプラグインの削除（「Uninstall」）は、選択中のプロファイルからファイルを消し、同梱されていたアプリ側も一緒に消す。反映にはゲートウェイの再起動が要る。アプリ側だけのプラグインは `desktop-plugins` フォルダーから消され、その場で解除される。どちらもカタログや Git からいつでも入れ直せる。

### インストールの流れ

インストールは、どこから始めても同じ確認ダイアログ（「Install plugin」）を通る。入口は「Git からインストール」、カタログの「+ インストール」（カードでは「+」）、`hermes://plugin/install?catalog=<名前>` などの `hermes://` リンク（配布ページの導入ボタンなど）、初回セットアップのチャットに出るプラグインカード。確認するまで自動でインストールされることはない。カタログに無い名前のリンクは拒否され、Git からの導入へ切り替わることもない。

| ダイアログの表示 | 内容 |
|---|---|
| Tier / 未確認 | カタログの項目は Tier のバッジ（`Official` / `Verified` / `Community`。英語表示）と「Nous がレビュー済み。」の説明が付く。カタログに無い Git リポジトリは「未確認」 |
| Repository / This package includes | 対象リポジトリと中身。「Agent plugin」「Desktop UI」のどちらを入れるかを選ぶ（少なくとも 1 つ） |
| 詳細設定 | バージョン（レビュー済みのピン / 最新のコミット）、Pin to commit（40 桁のコミット SHA。ブランチ名やタグは不可）、Force reinstall（導入済みでも入れ直す）、Install for profile（導入先のプロファイル）。未確認の Git URL では最初から開いている |
| Installs into … | 導入先。エージェント側はローカルなら選んだプロファイルのバックエンド、リモート接続中は接続先のバックエンド。アプリ側はこの端末の `desktop-plugins` フォルダー |
| This URL uses an insecure or local scheme. | `http://` などの URL への警告。`https://` か `git@` を使う |
| Source code | 「View repository」「View plugin files」で中身を確認できる |

- 未確認のリポジトリは、中身の検査（「Inspecting repository…」）が終わるまでインストールできない。カタログの項目は検査中でも始められる。
- 成功すると「N 個のツールを接続しました」「スキル（名前） の準備ができました」「ほかのツールは次のチャットで使えます」などが表示される。プラグインの MCP サーバーがつながらないときは「MCP サーバー（名前） は接続されていません」。
- 必要なキーが足りないときは、インストール後に「Set it up」から設定する（[[03_設定/11_ツールとキー|ツールとキー]]）。設定しないとそのプラグインのツールは失敗する。
- 失敗時は「Agent plugin install failed」「Desktop plugin install failed」の通知が出る。結果を待ちきれずに終わった場合は、ダイアログを閉じて一覧を再スキャンしてから入れ直す。

### デスクトッププラグインを手で置く

デスクトッププラグインの実体は `<HERMES_HOME>/desktop-plugins/<id>/plugin.js`（既定 `~/.hermes/desktop-plugins/`）で、全プロファイルで共有する。フォルダーアイコン（「デスクトッププラグインフォルダーを開く」）でこのフォルダーを開き、`<id>/plugin.js` を置くと、一覧に `on disk` の行として現れる。現れないときは再読み込み（再スキャン）ボタンを押し、`failed` が付いたら説明欄の赤字のエラーを読む。書き方と安全上の注意は [[03_設定/18_プラグイン|プラグイン]] を参照。

## 前提・操作・確認

- 前提: 「スキルとツール」画面が開け、スキル・Plugins・Connectors・ツールセットの各タブが表示されること。上部のスコープ選択で、設定したいプロファイルと接続先を選んでいること。
- 操作: 使いたいスキル・ツールセットのスイッチをオンにする。まだ入っていないスキルはスキルタブの「+ インストール」で入れる。「キーが必要」のものは先にキーを設定する。MCP サーバーの追加・ホスト型アプリの接続は Connectors タブ、プラグインの導入・有効化・自動更新は Plugins タブで行う。
- 期待結果: 有効にしたスキル・ツールセット・MCP ツールが、新しいセッションからエージェントで使える。エージェントプラグインはゲートウェイの再起動後に使える。デスクトッププラグインはスイッチを切り替えた時点で画面に反映される。
- 使えないとき: スコープ選択が意図したプロファイルを指しているか、トグルが ON か、「キーが必要」表示が残っていないか、対象の API キー設定を確認する（[[03_設定/11_ツールとキー|ツールとキー]]・[[03_設定/12_MCP|MCP]]）。ホスト型アプリは Nous へのサインインが必要。
