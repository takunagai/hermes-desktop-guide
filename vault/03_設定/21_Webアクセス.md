このコンピューターで動いている Hermes を **Webapp** としてネットワークに配信し、スマートフォンや別のコンピューターのブラウザーから開けるようにする。Webapp では Hermes Desktop と同じワークスペース（セッション、プロジェクト、設定）を使える。開く側は Nous アカウントでサインインする。

画面の説明文にあるとおり、**サインインした人はこのコンピューターでコマンドを実行できる**。配信するのは自分だけが使う端末・ネットワークに限る。

![設定 > Web アクセス 画面](@screenshots/settings-web-access.webp)

停止中の画面。LAN 上のアドレスはマスクしている。開始後の表示（実行中の状態や「停止」ボタン、「独自の URL」の入力欄）は実機では未確認で、ソースコードに基づいて書いている。

## 表示される条件

設定サイドバーの「ゲートウェイ」と「キーボードショートカット」のあいだに「Web アクセス」が表示される。子項目は無い。表示されるのは次の 2 つを満たすときだけ。

- Hermes Desktop のネイティブアプリで設定を開いている（Webapp 側の設定には出ない）。
- このマシンのゲートウェイに接続している。[[03_設定/10_ゲートウェイ|ゲートウェイ]]でリモートゲートウェイなど別マシンへ接続しているあいだは表示されない。

条件を満たさない状態で `?tab=web-access` のリンクから開くと、ゲートウェイの画面へ移動する。

## 画面の構成

冒頭に「スマートフォンや別のコンピューターから、Nous アカウントでサインインしてこのコンピューターの Hermes を開きます。サインインした人はこのコンピューターでコマンドを実行できます。」という説明があり、その下に次の要素が並ぶ。

| 要素 | 内容 |
|---|---|
| Web アクセス（状態） | 見出しの右に状態のバッジ。実行中 / 停止中 / 起動中 / 停止処理中 / 再起動が必要 / 利用できません のいずれか |
| 公開方法 | 「このネットワーク」と「独自の URL」の切り替え（後述）。初期の選択は「このネットワーク」 |
| アドレス | ほかのデバイスで開く URL。「このネットワーク」では、このコンピューターの LAN アドレスとポート 9120 の `http://` URL が開始前から表示され、配信中はリンクになる |
| 操作ボタン | 開始 / 停止。設定を保存したがゲートウェイの再起動が済んでいないときは「ゲートウェイを再起動」 |

開始の前提が満たされていないときは、アドレスの下に「先に「プロバイダー」で Nous アカウントにサインインしてください。」と表示され、「開始」は押せない。

### 公開方法

| 画面表示 | 動作 | 注意 |
|---|---|---|
| このネットワーク | 同じ Wi-Fi・LAN 上のデバイスから、このコンピューターのネットワークアドレスで開く | 接続は暗号化されない。画面にも「接続は暗号化されていません。同じネットワーク上の他の人が送受信の内容を読み取れる可能性があります。」と表示される。信頼できるネットワークでだけ使う。他のデバイスから到達できるアドレスが無いときは開始できない |
| 独自の URL | Tailscale Serve やトンネルなど、自分で用意した HTTPS のアドレス経由で開く | 入力欄に `https://` で始まる URL を入れる（`http://` では開始できない）。その URL への通信を、このコンピューターの `http://127.0.0.1:<ポート>`（既定ポート 9120）へ転送するよう、転送側で設定しておく |

## 手順: Web アクセスを開始する

- **前提**: ネイティブアプリでこのマシンのゲートウェイに接続している。[[03_設定/09_プロバイダー|プロバイダー]]で Nous アカウントにサインイン済み。「独自の URL」を使う場合は、HTTPS のアドレスから `http://127.0.0.1:9120` への転送を用意している。
- **操作**: 設定 > Web アクセス を開き、公開方法で「このネットワーク」か「独自の URL」を選ぶ（「独自の URL」なら URL を入力する）。「開始」を押す。
- **期待結果**: 準備、Webapp のビルド、Nous サインインの設定、ゲートウェイの再起動の順に進み、経過時間が表示される。ビルドには数分かかることがある。完了すると状態が「実行中」になり、開く URL が表示される。ほかのデバイスのブラウザーでその URL を開き、Nous アカウントでサインインすると Hermes が使える。
- **失敗時**:
  - 「チャットが実行中のため、ゲートウェイは再起動しませんでした」と出た場合は、チャットの終了後に「ゲートウェイを再起動」を押す。
  - 「ゲートウェイが 90 秒以内に Web アプリを提供しませんでした。」と出た場合や、状態が「利用できません」の場合は、表示された理由を確認して「ゲートウェイを再起動」を試す。続く場合は [[05_トラブルシューティング/01_問題の切り分け|問題の切り分け]] を参照する。
  - 「開始」が押せない場合は、Nous へのサインイン、「このネットワーク」ならネットワーク接続、「独自の URL」なら `https://` で始まる URL かを確認する。

## 手順: Web アクセスを停止する

- **前提**: 状態が「実行中」。
- **操作**: 設定 > Web アクセス で「停止」を押す。
- **期待結果**: ゲートウェイが再起動し、状態が「停止中」になる。ほかのデバイスからは開けなくなる。
- **失敗時**: 「オフにしましたが、ゲートウェイは再起動するまで Web アプリを提供し続けます。」と出た場合は、「ゲートウェイを再起動」を押すまで配信が続いている。必ず再起動まで済ませる。

> [!warning] 使わないときは停止する
> 配信中は、サインインできる人がこのコンピューターでコマンドを実行できる状態になる。外出先から一時的に使うだけなら、用が済んだら停止する。

## 背後の設定キー

画面の操作は専用の仕組みを通して次のキーを書き換える。画面にはホスト名とポートの入力欄は無い。

| 内部キー | 製品既定値 | 内容 |
|---|---|---|
| `webapp.enabled` | `false` | Webapp を配信するか |
| `webapp.host` | `127.0.0.1` | 待ち受けるアドレス |
| `webapp.port` | `9120` | 待ち受けるポート |
| `webapp.public_url` | 空 | 「独自の URL」で入力した公開 URL |

## Webapp で開いたときの違い

Webapp（ブラウザーで開いた Hermes）では、Desktop アプリと次の点が異なる。

### ゲートウェイ画面

設定の「ゲートウェイ」は「Hermes ホスト」の表示に置き換わり、配信元の Hermes ホストの URL と、サインイン中ならサインアウトボタンが出る。Webapp は常に配信元のホストを使う。ゲートウェイの切り替え、Hermes Cloud へのサインイン、保存済み接続の管理は Desktop アプリで行う。「Web アクセス」の画面も Webapp 側には出ない。

### キーボードショートカット

ブラウザー自身のショートカットとの衝突を避けるため、次の 8 アクションの既定キーが変わる。Desktop アプリの既定は変わらない。アクション名は内容を表す呼び名で、内部の ID を括弧内に示す。

| アクション | Desktop アプリ（既定） | Webapp・macOS | Webapp・Windows / Linux |
|---|---|---|---|
| 新しいセッション（`session.new`） | `⌘N` | `⌃⌘N` | `Alt+N` |
| 新しいタブ（`session.newTab`） | `⌘T` | `⌃⌘T` | `Alt+T` |
| 新しいウィンドウ（`session.newWindow`） | `⇧⌘N` | `⌃⇧⌘N` | `Alt+Shift+N` |
| 次のセッション（`session.next`） | `⌃Tab` / `⌃PageDown` | `⌃⌘]` | `Alt+]` |
| 前のセッション（`session.prev`） | `⌃⇧Tab` / `⌃PageUp` | `⌃⌘[` | `Alt+[` |
| ターミナルを閉じる（`view.closeTerminal`） | `⌃⇧W` | `⌃⇧W`（変わらない） | `Alt+Shift+W` |
| タブを閉じる（`view.closeTab`） | `⌘W` | `⌃⌘W` | `Alt+W` |
| 閉じたタブを開き直す（`view.reopenTab`） | `⇧⌘T` | `⌃⇧⌘T` | `Alt+Shift+T` |

Desktop アプリ列は macOS の表記。Windows / Linux では `⌘` が `Ctrl` になる。Windows / Linux でも、Chromium のアプリウィンドウ（`--app=` で開いた単独ウィンドウ）では Desktop アプリと同じ既定に戻る。キーの変更方法は [[03_設定/17_キーボードショートカット|キーボードショートカット]] を参照。

### 通知とマイク

- **通知**: 設定の「通知」に Webapp 専用の「ブラウザー通知」行が加わり、「許可」でブラウザーの通知を有効にする。通常の HTTP で開いている場合は通知が出ず、タブのタイトルが点滅するだけになる。詳細は [[03_設定/15_通知|通知]] を参照。
- **マイク**: 音声入力には安全な接続が必要で、Webapp を HTTPS か、`127.0.0.1` への SSH トンネル経由で開く必要がある。「このネットワーク」の HTTP 接続では使えない。
