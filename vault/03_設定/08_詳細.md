スリープ防止、F12 の無効化、実行バックエンド、各種上限、サブエージェント、更新時のローカル変更処理を設定する。通常は既定値から始める。

![](@editorial/editorial-16-hermes-hands-orb.webp)

![設定 > 詳細 画面](@screenshots/settings-advanced.webp)

表示値は環境依存の例（最大エージェントステップなど、既定値から変更済みの値を含む）。

> [!note] 「適用対象」チップ（プロファイルが 2 つ以上あるとき）
> プロファイルを 2 つ以上作成していると、画面上部に「適用対象」という見出しとプロファイル名のチップ列が表示される。チップを選ぶと「このページの変更は「◯◯」プロファイルに適用されます。」と表示され、この画面の編集がそのプロファイルの `config.yaml` に書き込まれる。選択は設定画面の他のページへ移動しても保持される。プロファイルが 1 つだけの環境では表示されない。

> [!note] 自動保存は変更したキーだけを書き込む
> この画面（および config 由来の各設定ページ）の自動保存は、ページを開いた時点のスナップショットと比較して**差分のあるキーだけ**をゲートウェイへ送る。`hermes config set` や `config.yaml` の直接編集で外から変えたキーを、画面が古い値で上書きすることはない。保存要求は順番に処理されるため、先に出した保存が後から届いて新しい値を巻き戻すこともない。

## コンピューターをスリープさせない

画面最上部のトグル。説明文は「本体のスリープを防ぎ、長時間や夜通しの実行を継続します。画面は暗転できます。」。

- **保存先が他の項目と違う**: `config.yaml` のキーではなく、端末ごとに保存されるデバイスローカル設定。プロファイルや別のマシンには同期されない。既定はオフ。
- **動作**: オンにすると OS のパワーセーブブロッカー（`prevent-app-suspension`）を保持し、システムのスリープだけを防ぐ。ディスプレイの暗転は妨げない。アプリ終了時に自動解除され、次回起動時は保存済みのオン／オフ状態が復元される。
- **用途**: 夜通しの長時間エージェント実行やバッチ作業を、本体スリープで中断させたくないときにオンにする。

手順 ─ 前提: 設定 → 詳細を開く。操作: 最上部の「コンピューターをスリープさせない」をオンにする。期待結果: 即時反映され、以後この端末では実行中に本体がスリープしなくなる（アプリ再起動後も維持）。失敗時: トグルが表示されない場合は [[03_設定/14_情報|情報]] でアプリのバージョンを確認する。

## Disable F12 DevTools

「コンピューターをスリープさせない」の直下、「クイック入力」の直上にあるトグル。日本語リソース未整備のため、日本語 UI でもラベルと説明文は英語のまま表示される（説明文: 「Block F12 from opening Developer Tools. Ctrl+Shift+I (or Cmd+Opt+I on Mac) still works.」）。

- **動作**: オンにすると、F12 キーで開発者ツール（DevTools）が開かなくなる。`Ctrl+Shift+I`（Mac は `Cmd+Opt+I`）のショートカットは引き続き有効。
- **保存先**: `config.yaml` ではなく端末ごとのデバイスローカル設定（`localStorage: hermes.desktop.disableF12.v1`）。既定はオフ。プロファイルや別のマシンには同期されない。
- **用途**: F12 をターミナルやエディタ側のキーとして使いたい、あるいは誤操作で DevTools が開くのを防ぎたい場合にオンにする。

## ツールと実行

| 画面表示（主） | 内部キー（サブ） | 製品既定値 | 推奨 |
|---|---|---:|---|
| 有効なツールセット | `toolsets` | `hermes-cli` | 必要なものだけ |
| 実行バックエンド | `terminal.backend` | `local` | 通常 `local`、隔離時はコンテナ等 |
| コマンドタイムアウト | `terminal.timeout` | `180` 秒 | 180～600秒 |
| ターミナル出力上限 | `tool_output.max_bytes` | `50000` bytes | 既定値 |
| ファイルページ上限 | `tool_output.max_lines` | `2000` 行 | 既定値 |
| 行長上限 | `tool_output.max_line_length` | `2000` 文字 | 既定値 |

### 有効なツールセット

カンマ区切りで有効化するツールセット ID を指定する。`hermes-cli` は Hermes の標準ツール群。MCP やプラグイン由来の候補はインストール状態により変わるため固定リストではない。存在しない ID、不要な高権限ツールセットを追加しない。

> [!warning] 全消しの確認ダイアログ
> 欄を空にする編集（全選択して Backspace など）を行うと、適用前に破棄確認のダイアログが出る。文言は英語のまま「Remove all enabled toolsets? This disables memory, terminal, web search, delegation, and most other tools until you re-enable them.」。承認すると自動保存で即座に反映され、メモリ・ターミナル・Web 検索・委譲を含むほとんどのツールが無効になる。取り消し操作は無いので、意図しない場合はキャンセルする。

### 実行バックエンド

| 画面表示（主） | 保存値（内部） | 既定 | 動作 |
|---|---|---|---|
| Local | `local` | はい | 現在の Mac 上で実行 |
| Docker | `docker` | いいえ | コンテナ分離。Docker の準備が必要 |
| Singularity | `singularity` | いいえ | HPC 向け Singularity / Apptainer |
| Modal | `modal` | いいえ | Modal のクラウドサンドボックス |
| Daytona | `daytona` | いいえ | Daytona の管理ワークスペース |
| Ssh | `ssh` | いいえ | リモートホスト |

バックエンド変更だけで安全が保証されるわけではない。ネットワーク、マウント、資格情報、破棄方針も確認する。

> [!note] ヘルスプローブ付きバックエンドピッカー
> 詳細画面のドロップダウンとは別に、サイドバーの「スキルとツール」→「ツールセット」タブで terminal ツールセットを開くと、「実行バックエンド」パネルから同じ `terminal.backend` を切り替えられる。各バックエンドの行にヘルスプローブの結果（Docker デーモンへの到達性、SSH ホストの設定有無、Modal / Daytona の資格情報の有無など）が「準備完了」「セットアップが必要」「利用不可」のピルで表示され、使用中のバックエンドには「使用中」が付く。行のクリックは詳細の展開だけを行い、切り替えは「このバックエンドを使う」ボタンで明示的に確定する。「セットアップが必要」なバックエンドも選択自体はでき、不足している項目が案内される。切り替えは新しいセッションから適用される。

> [!note] 実行イメージ欄
> 実行バックエンドの直下に、各バックエンドで使うコンテナ／環境イメージを指定する欄がある。バックエンド選択に関係なく常に表示される。

| 画面表示（主） | 内部キー（サブ） | 製品既定値 |
|---|---|---|
| Docker イメージ | `terminal.docker_image` | `nikolaik/python-nodejs:python3.11-nodejs20` |
| Singularity イメージ | `terminal.singularity_image` | `docker://nikolaik/python-nodejs:python3.11-nodejs20` |
| Modal イメージ | `terminal.modal_image` | `nikolaik/python-nodejs:python3.11-nodejs20` |
| Daytona イメージ | `terminal.daytona_image` | `nikolaik/python-nodejs:python3.11-nodejs20` |

各欄は対応するバックエンドを選んだときに使われる。`local` と `ssh` はイメージ指定を持たない。

### Docker のネットワーク遮断（config.yaml のみ）

`terminal.docker_network`（既定 `true`）を `false` にすると、Docker バックエンドのコンテナが `--network=none` で起動し、コマンドがネットワークへ一切到達できないエアギャップ実行になる。詳細画面には対応する入力欄がなく、`config.yaml` の直接編集または環境変数 `TERMINAL_DOCKER_NETWORK` で設定する。

### 出力・時間上限

- **コマンドタイムアウト**: ターミナルコマンドを待つ最大秒数。短すぎるとビルドやテストを途中終了し、長すぎると停止した処理を待ち続ける。
- **ターミナル出力上限**: 1つのツール結果へ保持する最大バイト数。超過部分は切り詰められる。
- **ファイルページ上限**: ファイル表示・ページングで保持する最大行数。
- **行長上限**: 1行あたりの最大文字数。巨大な JSON や minify 済みファイルの1行を制限する。

## チェックポイントとエージェント

| 画面表示（主） | 内部キー（サブ） | 製品既定値 | 推奨 |
|---|---|---:|---|
| チェックポイント上限 | `checkpoints.max_snapshots` | `20` | 20 |
| 最大エージェントステップ | `agent.max_turns` | 空欄（上限なし） | 既定のまま。自動化用途で歯止めが要るときだけ正の整数 |
| API 再試行回数 | `agent.api_max_retries` | `3` | 3 |
| サービス階層 | `agent.service_tier` | 空欄 | 空欄または `auto` |
| ツール使用の強制 | `agent.tool_use_enforcement` | `auto` | `auto` |

### 上限・再試行

- **チェックポイント上限**: 1プロジェクトで保持するスナップショット数。古いものは保守処理の対象になる。
- **最大エージェントステップ**: 1ターンで許すツール呼び出し反復の上限。製品既定は空欄（`null`）で、**上限なし**として扱われる。`0` 以下の数値や `none` / `unlimited` などの文字列も上限なしの表記として解釈される。正の整数を入れるとその回数で打ち切る。大きいほど長い自律作業ができるが、費用、時間、変更範囲も増える。小さくしすぎると作業の途中で打ち切られる。画面に既定値以外の数値が見えている場合は、この環境で明示設定された値。
- **API 再試行回数**: 接続切断、タイムアウト、5xx などで Hermes が API 呼び出し全体を再試行する回数。フォールバックを早く使いたい場合は小さくする。

### サービス階層の全候補

| 画面表示（主） | 保存値（内部） | 既定 | 動作 |
|---|---|---|---|
| (なし) | 空文字 | はい | `service_tier` パラメーターを明示せず、プロバイダー・アカウントの標準へ委ねる |
| Auto | `auto` | いいえ | API へ自動選択を要求する。具体的な扱いは対応プロバイダー側が決める |
| Default | `default` | いいえ | API の標準処理階層を明示する |
| Flex | `flex` | いいえ | 対応 API の柔軟処理階層を要求する。待ち時間、価格、利用可否はプロバイダー仕様に依存 |

接続先が対応しない値は無視または API エラーになる場合がある。xAI など、`service_tier` を受け付けない経路では Hermes が除去する場合もある。

### ツール使用の強制で入力できる全形式

この項目は自由入力欄。次の値が意味を持つ。

| 入力 | 動作 |
|---|---|
| `auto` | `gpt`, `codex`, `gemini`, `gemma`, `grok`, `glm`, `qwen`, `deepseek` を名前に含むモデルへ、実際にツールを呼ぶよう追加指示を注入 |
| `true` | モデル名に関係なく常に追加指示を有効化 |
| `false` | モデル名に関係なく無効化 |
| モデル名部分文字列のリスト | 指定文字列をモデル名に含む場合だけ有効化。JSON インポートや設定ファイル編集向け |

デスクトップの入力欄では通常 `auto`, `true`, `false` を使う。リスト形式は `["gpt", "qwen"]` のような構造値であり、単純な文字列として入力すると同じ意味にならない場合がある。

## サブエージェント

| 画面表示（主） | 内部キー（サブ） | 製品既定値 | 推奨 |
|---|---|---:|---|
| サブエージェントモデル | `delegation.model` | 空欄 | 空欄（自動） |
| サブエージェントプロバイダー | `delegation.provider` | 空欄 | 空欄（自動） |
| サブエージェントターン上限 | `delegation.max_iterations` | `250` | 既定のまま。費用を抑えたいときは下げる |
| 並列サブエージェント | `delegation.max_concurrent_children` | `10` | 既定のまま。レート制限に当たるなら下げる |
| サブエージェントタイムアウト | `delegation.child_timeout_seconds` | `0`（なし） | 既定のまま |
| サブエージェント推論強度 | `delegation.reasoning_effort` | 空欄 | 空欄または `medium` |

> [!note] 旧キー `delegation.max_async_children` は廃止
> 旧キー `delegation.max_async_children` は廃止され、「並列サブエージェント」（`delegation.max_concurrent_children`）に統合された。バッチ並列とバックグラウンド委譲の同時実行数を1本の上限で制御し、上限を超えた非同期ディスパッチは同期実行へフォールバックする。旧キーが `config.yaml` に残っている場合は設定の移行処理でキー自体が削除される。旧値が 3 を超え、かつ現行の「並列サブエージェント」値より大きいときにかぎり、その大きい値へ引き上げられる。旧値が 3 以下、または現行値以下のときは現行値がそのまま残る。

### モデルとプロバイダー

- **モデルが空欄**: 親エージェントのモデルを継承する。
- **プロバイダーが空欄**: 親エージェントのプロバイダーと認証情報を継承する。
- **片方または両方を指定**: 子エージェントだけを安価・高速・高精度な別構成へ分離する。実在する ID を使う。

### 推論強度の全候補

空欄を含めて8候補ある。

| 画面表示（主） | 保存値（内部） | 既定 | 動作 |
|---|---|---|---|
| (なし) | 空文字 | はい | 親エージェントの推論強度を継承 |
| Minimal | `minimal` | いいえ | 最小限の推論。速度と費用を優先 |
| Low | `low` | いいえ | 軽い推論 |
| Medium | `medium` | いいえ | バランス型 |
| High | `high` | いいえ | 複雑な問題向け。遅延とトークンが増え得る |
| Xhigh | `xhigh` | いいえ | 高負荷推論 |
| Max | `max` | いいえ | GPT-5.6 / Codex 系の最上位ティア向け |
| Ultra | `ultra` | いいえ | 最上位。対応プロバイダーは限られる |

モデルが対応する値だけ有効。並列数を増やすと API レート制限、費用、同一ファイルへの競合が増える。

### サブエージェントの上限

- **ターン上限**: 子エージェント1体ごとの反復上限。
- **並列サブエージェント**: 同時実行できる子の最大数。最低1。既定の `10` は API のレート制限や同一ファイルへの競合が起きやすい値でもあるため、問題が出る環境では下げる。
- **タイムアウト**: 子1体の経過時間上限。既定 `0` はタイムアウトなしで、子は API エラー、ツールエラー、反復上限だけで停止する。正の秒数を設定すると強制打ち切りになる（最低30秒）。

## Codex ランタイム（app-server）の表示と圧縮

Codex プロバイダー（codex CLI ランタイム / app-server）を使う場合の表示と圧縮。以下の設定キーは詳細画面に入力欄がなく、変更は `config.yaml` で行う。

- **ツール実行のライブカード表示**: app-server ランタイムのツール実行は、TUI とデスクトップで進行中のライブツールカードとして表示される。セッション再開後もライブカードと履歴側のエントリが正しく対応付けられる。
- **コメンタリーの可視化**: Codex Responses 系モデルが進行状況を語る「コメンタリー」チャンネルが、可視の中間メッセージとしてストリーム表示される。制御キーは `display.show_commentary`（既定 `true`）。`false` にするとコメンタリーは推論チャンネルへ回り、推論表示が有効な場合だけ見える。
- **スレッド圧縮**: `compression.codex_app_server_auto`（既定 `native`）で app-server スレッドの圧縮を制御する。Codex エージェントが実際のスレッドコンテキストを所有するため、Hermes 側の要約では縮小できない。`native` は Codex 自身が圧縮タイミングを決め、`hermes` にすると Hermes の圧縮しきい値が `thread/compact/start` を起動する。`off` は自動圧縮を起動しない（Codex 側のネイティブ圧縮は起こり得る）。
- 積み立て済みのレート上限リセットを消化する `/usage reset` は [[06_リファレンス/05_スラッシュコマンド一覧|スラッシュコマンド一覧]] を参照。

## アプリ内更新時のローカル変更

| 画面表示（主） | 保存値（内部） | 既定 | 動作 | 推奨 |
|---|---|---|---|---|
| Stash | `stash` | はい | ローカルのソース変更を一時退避して更新 | 推奨 |
| Discard | `discard` | いいえ | ローカル変更を破棄して更新 | 意図的に破棄する場合のみ |

設定キーは `updates.non_interactive_local_changes`、製品既定値は `stash`。ターミナルからの更新では別途確認される。

> [!danger] `discard`
> Hermes のインストールソースを直接編集している場合、未コミット変更が失われる。更新前に Git 状態とバックアップを確認する。

## クイック入力

グローバルショートカットで、ほかのアプリを使っている最中でもミニ入力欄を呼び出し、その場でプロンプトを送信できる。**既定は有効**で、既定のショートカットは `⌘ ⇧ Space`（Windows・Linux は `Ctrl + Shift + Space`）。

- Hermes のウィンドウを前面に出さずに指示を投げられる。
- 保存先は `config.yaml` ではなくデバイスローカル設定（`store/quick-entry`）。スリープ防止と同じく端末ごとの設定で、プロファイルや別のマシンには同期されない。
- グローバルショートカットは OS 全体で有効になるため、他アプリのショートカットと競合しないか確認する。

### 更新前バックアップ（config.yaml のみ）

`updates.pre_update_backup` は3値の文字列（既定 `quick`）。詳細画面には入力欄がなく、`config.yaml` で設定する。

| 値 | 動作 |
|---|---|
| `quick`（既定） | ペアリング情報 JSON、cron ジョブ、`config.yaml`、`.env`、`auth.json`、プロファイル別 DB などの重要な小さい状態ファイルだけを更新前に `state-snapshots/` へ退避する軽量スナップショット。1 GiB を超えるファイルは警告付きでスキップされる。復元は `/snapshot` |
| `full` | `quick` のスナップショットに加えて、HERMES_HOME 全体の zip バックアップを `backups/` へ作成する（`hermes import` で復元）。大きな環境では数分かかる。`--backup` で単回だけ強制できる |
| `off` | 更新前バックアップを行わない。`--no-backup` で単回だけ強制できる |

旧来のブール値は互換のため解釈される。`true` は `full`、`false` は `off` と同じ。保持数は `full` の zip が `updates.backup_keep`（既定 `5`）、`quick` のスナップショットは常に最新1件。

## 画面に入力欄が無い設定値

詳細画面に入力欄がなく、`config.yaml` でだけ設定するキー（前述の `terminal.docker_network`・`updates.pre_update_backup` も同じ扱い）。

| 設定キー | 既定 | 内容 |
|---|---|---|
| `agent.verify_on_stop` | オフ | コードを編集した後、検証の証拠が揃うまで最終回答を受け付けない「検証クロージャ」。`true` で常時オン、`auto` で対話的なコーディング画面（CLI / TUI / デスクトップ）だけオン |
| `agent.restart_after_turn_timeout` | `1800` 秒 | `/restart` などのインバンド再起動で、実行中のターンの完了を待つ上限。`0` で待たずに即停止 |
| `agent.stall_guards` | オン | 「続けます」と言って何もしないなど、ターンが停滞したときの保護を有効にする |
| `agent.empty_response_guard.enabled` | オン | 空応答が続いたときの保護。`agent.empty_response_guard.cost_threshold_usd`（既定 `0.25`）が費用のしきい値 |
| `agent.turn_liveness.timeout_s` | `600` 秒 | ターンの生存監視。`agent.turn_liveness.poll_s`（既定 `15` 秒）間隔で活動を確認し、この時間無活動なら停滞とみなす |
| `tools.tool_search.max_search_limit` | `25` | `tool_search` でモデルが 1 クエリあたりに要求できる件数の上限（1～50） |
| `terminal.degraded_mode` | `warn` | サンドボックスが劣化した状態になったときの扱い。警告して続けるか、失敗させるか |
| `terminal.docker_shm_size` | `1g` | Docker バックエンドの共有メモリサイズ |
| `terminal.vercel_runtime` | `node24` | Vercel 実行環境のランタイム |
| `desktop.auto_continue.enabled` | オン | 中断したターンを自動で復旧して継続する |
| `desktop.auto_continue.freshness_minutes` | `15` | 自動継続の対象とする鮮度（分） |
| `desktop.auto_continue.max_attempts` | `2` | 自動継続を試みる回数の上限 |
| `tool_loop_guardrails.loop_caps.max_web_searches` | `50` | ツールループ中の web 検索回数の上限。`0` で無制限 |
| `tool_loop_guardrails.loop_caps.max_subagents` | `50` | ツールループ中に起動するサブエージェント数の上限。`0` で無制限 |
| `database.journal_mode` | `wal` | セッションデータベースのジャーナルモード |

- **`database.journal_mode`**: fsync の保証が弱い共有ファイルシステム（virtiofs・NFS・SMB）上に HERMES_HOME を置く場合は `DELETE` へ切り替える。

### アウトバウンドの強制プロキシ（`proxy`）

`proxy` セクション（**既定オフ**）は、リモートのターミナルサンドボックスからのアウトバウンド通信を iron-proxy 経由へ強制する egress 保護。

| 設定キー | 既定 | 内容 |
|---|---|---|
| `proxy.tunnel_port` | `9090` | トンネルに使うポート |
| `proxy.enforce_on_docker` | オン | proxy が有効なのに起動していない場合、直接通信を拒否する |

> [!note] 音声プロバイダーのドロップダウン（音声画面の設定）
> `config.yaml` の `tts.providers.<名前>` / `stt.providers.<名前>`（旧形式のトップレベル `tts.<名前>` / `stt.<名前>` も可）に定義したユーザー定義のコマンド型プロバイダーが、[[03_設定/07_音声|音声]] 画面の「音声合成プロバイダー」「音声認識プロバイダー」の候補に列挙される。別のプロバイダーへ切り替えた後も候補に残るため、`config.yaml` を手編集せずに再選択できる。
