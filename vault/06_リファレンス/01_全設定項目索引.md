設定画面の順序と項目のチェック用索引。実機の日本語 UI と、同一コミットのソース（設定画面定義・日本語ラベル `i18n/ja.ts`・バックエンド既定値 `DEFAULT_CONFIG`）を突き合わせて作成している。採取と照合の履歴は [[06_リファレンス/02_バージョンと調査根拠|バージョンと調査根拠]] を参照。

設定画面は **18 画面**で構成される。MCP は設定タブになく、Capabilities ページ（`/skills?tab=mcp`）にある（本ページ末尾の「MCP」を参照）。ナビの並び順は次のとおり（区切り線 2 本を含む）。

1. 設定セクション 9 つ（モデル / チャット / 外観 / ワークスペース / 安全性 / Browser / メモリとコンテキスト / 音声 / 詳細）
2. 通知 → 請求
3. ─ 区切り ─ プロバイダー（サブ: アカウント / API キー / カスタムエンドポイント / ローカルモデル） → ゲートウェイ → キーボードショートカット → ツールとキー（サブ: ツール / 設定） → Plugins → アーカイブ済みチャット
4. ─ 区切り ─ 情報

「Browser」「Plugins」は日本語 UI でもナビラベルが英語のまま（日本語リソース未整備）。プロバイダーの「ローカルモデル」サブビューは `hermes desktop --local` で起動したときだけ表示され、通常起動では 3 件になる。

表の「画面表示（主）」は実際に見える文字列、「内部キー（サブ）」は設定 API・設定ファイル・`.env`・デスクトップ保存領域で使う名前。内部キーだけを画面ラベルとして扱わない。ボタンなど永続キーを持たないものは、内部操作名または「操作・保存キーなし」、既定値は「該当なし」と記載する。「未設定（実効: 値）」は、保存値は空だが実行時に括弧内へ解決されることを示す。一部の画面は日本語リソースが未整備で、本文が英語表示のまま（ナビラベルのみ日本語）。該当箇所は行内に明記する。

## 画面をまたぐ機能

| 画面表示（主） | 内部キー・操作（サブ） | 製品既定値・初期状態 |
|---|---|---|
| 検索 ⌘K（設定カード上端のピル） | ⌘K コマンドパレットの設定スコープを開く。設定画面で入力欄の外に文字を打っても開く | 常時表示 |
| 適用対象（プロファイルチップ列） | UI 状態 `$settingsScopeOverride`。この画面の編集をどのプロファイルの `config.yaml` に書くかを選ぶ | アクティブプロファイル。プロファイルが 2 つ以上あるときだけ表示 |
| ディープリンク | `/settings?tab=<画面>&key=<ENV_KEY>` / `?tab=plugins&plugin=<id>` で該当行へスクロールと強調 | 該当なし |

「適用対象」が出る画面は、モデル / チャット / ワークスペース / 安全性 / Browser / メモリとコンテキスト / 音声 / 詳細 / ツールとキー（いずれも `config.yaml` 由来）。外観・通知・請求・ゲートウェイ・キーボードショートカット・Plugins・アーカイブ済みチャット・情報には出ない（端末ローカルまたはマシン単位の設定）。Plugins の Agent plugins には別に「Applies to:」セレクタがある。

推論レベルの選択肢は **8 段階**: Off（`none`）/ 最小（`minimal`）/ 低（`low`）/ 中（`medium`）/ 高（`high`）/ 特高（`xhigh`）/ 最大（`max`）/ ウルトラ（`ultra`）。サブエージェント推論強度（`delegation.reasoning_effort`、08 詳細）も同じ段階を使う。MoA の参照・集約スロットにはスロット別 `reasoning_effort` を保存できるが、デスクトップ画面には編集欄がない（設定ファイル側の値を保持するのみ）。既定プリセット `default` に `aggregator_temperature` / `reference_temperature` は含まれない。

メインモデル直下の Defaults ブロックには推論レベル（`agent.reasoning_effort`、既定 `medium`）が表示され、対応モデルでは「高速（Fast）」トグル（`agent.service_tier`: `fast` / `normal`）も並ぶ。設定画面の補助モデルは上記 8 タスクのみ（「ウェブ抽出」は廃止され、`auxiliary.web_extract.*` は既定値定義から消えている）。モデル割り当て API には `auxiliary.triage_specifier` / `kanban_decomposer` / `profile_describer` も含まれるが画面には出ない。config にはさらに `memory_query_rewrite` / `tts_audio_tags` / `goal_judge` / `monitor` の各タスク、`auxiliary.background_review.*`（既定 オン・`max_input_tokens` は `600000`）、`auxiliary.transient_retries`（既定 `2`）があり、`memory_query_rewrite` を除くほぼ全補助タスクで `reasoning_effort`（既定 空欄 = プロバイダー既定）を指定できる。メインモデルの変更がスケジュール済みジョブに影響する場合は「スケジュール済みジョブの確認が必要です」の警告が出る。

## 06 Browser

→ [[03_設定/19_Browser|「Browser」の設定ページを見る]]

ナビラベル・見出しは日本語 UI でも英語 `Browser`（日本語リソース未整備）。1 行目はラベル・説明とも英語表示。

| 画面表示（主） | 内部キー（サブ） | 製品既定値 |
|---|---|---|
| Use My Real Browser Profile（英語表示） | `browser.use_real_profile` | オフ |
| ブラウザーのプライベート URL | `browser.allow_private_urls` | オフ |
| プライベート URL にはローカルブラウザーを使用 | `browser.auto_local_for_private_urls` | オン |

`browser.use_real_profile` は、既定ブラウザ（Chrome / Edge / Brave / Chromium などの Chromium 系のみ）のプロファイルを Hermes 管理のスナップショットへ複製し、同梱 Chromium で使う設定。実プロファイルは直接開かず、オフに戻すとスナップショットは削除される。同じトグルは「スキルとツール」→ ツールセット → Browser の先頭に日本語ラベル「実際のブラウザプロファイルを使用」でも出る（初回オン時は同意ダイアログあり）。`browser.real_profile_pin`（空欄）/ `browser.real_profile_autoclose`（オフ）/ `browser.backend`（空欄）/ `browser.snapshot_threshold`（`15000`）/ `browser.extension_control.enabled`・`developer_mode`（各オフ）は GUI 項目を持たない config 専用キー。
