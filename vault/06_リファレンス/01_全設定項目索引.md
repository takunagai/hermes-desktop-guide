設定画面の順序と項目のチェック用索引。実機の日本語 UI と、同一コミットのソース（設定画面定義・日本語ラベル `i18n/ja.ts`・バックエンド既定値 `DEFAULT_CONFIG`）を突き合わせて作成している。採取と照合の履歴は [[06_リファレンス/02_バージョンと調査根拠|バージョンと調査根拠]] を参照。

設定画面は **19 画面**で構成される。MCP は設定画面になく、「スキルとツール」ページの Connectors タブ（`/capabilities?tab=connectors`）にある（本ページ末尾の「MCP」を参照）。ナビの並び順は次のとおり（区切り線 3 本を含む）。

1. 設定セクション 9 つ（モデル / チャット / 外観 / ワークスペース / 安全性 / Browser / メモリとコンテキスト / 音声 / 詳細）。Browser の直後に「パスワードとログイン」が入る
2. 通知 → 請求
3. ─ 区切り ─ プロバイダー → ゲートウェイ → キーボードショートカット → ツールとキー → セッション
4. ─ 区切り ─ プラグイン
5. ─ 区切り ─ 情報

各画面はサイドバーの子項目（サブページ）を持つ。選択中の画面だけ子項目が開き、画面を開くと先頭の子項目が表示される。各ページの上部にはパンくず（「設定 > 画面 > サブページ」）が出て、画面ごとの大見出しは出ない。子項目の一覧は本ページの各見出しの直下に示す。長いラベルはサイドバーで省略表示される（「パスワードとログ…」「メモリとコンテキ…」「キーボードショー…」）。

「Browser」は日本語 UI でもナビラベルが英語のまま（日本語リソース未整備のため英語表示）。プロバイダーの「ローカルモデル」は macOS / Windows / Linux（x64・arm64）では常に表示され、それ以外の環境だけ `hermes desktop --local` での起動が要る。

表の「画面表示（主）」は実際に見える文字列、「内部キー（サブ）」は設定 API・設定ファイル・`.env`・デスクトップ保存領域で使う名前。内部キーだけを画面ラベルとして扱わない。ボタンなど永続キーを持たないものは、内部操作名または「操作・保存キーなし」、既定値は「該当なし」と記載する。「未設定（実効: 値）」は、保存値は空だが実行時に括弧内へ解決されることを示す。デバイスローカルの項目で「`store/…`」と書いたものは、デスクトップの保存モジュール名（`config.yaml` には入らない）。一部の画面は日本語リソースが未整備で、本文が英語表示のまま（ナビラベルのみ日本語）。該当箇所は行内に明記する。

## 画面をまたぐ機能

| 画面表示（主） | 内部キー・操作（サブ） | 製品既定値・初期状態 |
|---|---|---|
| 検索 ⌘K（設定カード上端のピル） | ⌘K コマンドパレットの設定スコープを開く。設定画面で入力欄の外に文字を打っても開く。全画面の手作りの設定行とサブページそのもの（例: 情報 › アンインストール）が候補に出る | 常時表示 |
| サブページ（サイドバーの子項目）とパンくず | URL の `page=` で指定。指定が無いときは先頭の子項目へ移る | 先頭の子項目 |
| 適用対象（プロファイルチップ列） | UI 状態 `$settingsScopeOverride`。この画面の編集をどのプロファイルに書くかを選ぶ。既定以外のプロファイルを編集中は注記「…を編集中」が強調表示される | アクティブプロファイル。プロファイルが 2 つ以上あるときだけ表示 |
| ディープリンク | `/settings?tab=<画面>&page=<サブページ>`、`?setting=<行 ID>`（子ページを開いてから該当行へスクロールと強調）、`?pview=keys&key=<ENV_KEY>`（プロバイダーの API キー）、`?tab=plugins&plugin=<id>`（各プラグインの設定ページ） | 該当なし |

「適用対象」が出る画面は、モデル / チャット / ワークスペース / 安全性 / Browser / メモリとコンテキスト / 音声 / 詳細 / ツールとキー（いずれも `config.yaml` 由来）と、プロバイダー（アカウント / API キー / カスタムエンドポイント）、パスワードとログイン、プラグイン。外観・通知・請求・ゲートウェイ・キーボードショートカット・セッション・情報には出ない（端末ローカルまたはマシン単位の設定）。プロバイダーのローカルモデルは常にアクティブプロファイルを対象にする（読み取り専用の注記を表示）。

旧 URL は新しい場所へ転送される。`?tab=mcp` は「スキルとツール」の Connectors タブ、`?tab=connections` はゲートウェイ、旧パラメータ `aux=` / `session=` / `kind=`・`label=`・`origin=` はそれぞれ補助モデル / セッションのアーカイブ / パスワードとログインの追加ダイアログへ振り分けられる。

推論レベルの選択肢は **8 段階**: Off（`none`）/ 最小（`minimal`）/ 低（`low`）/ 中（`medium`）/ 高（`high`）/ 特高（`xhigh`）/ 最大（`max`）/ ウルトラ（`ultra`）。サブエージェント推論強度（`delegation.reasoning_effort`、10 詳細）も同じ段階を使う。速度の `auto`（各ターンの最初の `agent.fast_auto_seconds` 秒、既定 `60`）と `cold`（セッションの最初のターンだけ）は `/fast` と `config.yaml` から選ぶ。

補助タスクの一覧の末尾には、プラグインが登録した補助タスクが並ぶ。補助タスクの推論強度は「継承」を選ぶと `reasoning_effort` を `null` で保存し、メインモデルの推論強度に従う。config にはこのほか `memory_query_rewrite` / `tts_audio_tags` / `goal_judge` / `monitor` / `background_review` の各補助タスク、`auxiliary.transient_retries`（既定 `2`）、`auxiliary.title_generation.model_upgrade_enabled`（既定 オン。オフでモデルを呼ばずに即時の派生タイトルだけを使う）がある。メインモデルの変更がスケジュール済みジョブに影響する場合は「スケジュール済みジョブの確認が必要です」の警告が出る。MoA の参照・集約スロットにはスロット別 `reasoning_effort` を保存できるが、デスクトップ画面には編集欄がない。
