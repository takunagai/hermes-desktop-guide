Hermes の利用者影響をバージョンごとに一覧化したページ。設定画面に直接現れない破壊的変更や、Desktop アプリの外（CLI・ブラウザのダッシュボード）で提供される機能も、読者が把握できるようにここへまとめる。

## v0.21.0 → v0.22.1（The Threshold Release）

> [!note] 対象バージョン
> v0.21.0（タグ `v2026.8.31`）から v0.22.1（タグ `v0.22.1`、2026-10-14 公開）への変更点。v0.22.1 は Windows Store・プラグイン更新まわりの修正を中心とするパッチリリースで、利用者から見える変更の大半は直前の大型リリース **v0.22.0**（タグ `v0.22.0`、2026-10-14 公開、コードネーム「The Threshold Release」）に含まれる。v0.22.0 は v0.21.0 以降の約 24,200 コミット・約 6,080 マージ済み PR・約 15,600 ファイル変更・約 7,180 Issue 解決、約 2,520 人のコントリビューターを含み、v0.21.0 の周期の約 2.5 倍の規模になった。中間リリース v0.21.1〜v0.21.7（タグ `v2026.9.7` / `v2026.9.11` / `v2026.9.14` / `v2026.9.21` / `v2026.9.24` / `v0.21.6` / `v0.21.7`）の内容も v0.22.0 のリリースノートに統合されている。リリースタグはこの版から日付形式ではなく SemVer 形式になった。コードネームは「境界・戸口の神」としての Hermes に由来し、初めて使う人が戸口を越えて Hermes と話し始めるまで（初回セットアップ・無料の体験モデル・Connectors・ローカルモデル・安定版リリース）を主題にしている。

### 主な新機能

- **初回起動のガイド付きセットアップ**: Hermes を使ったことのないコンピューターでデスクトップアプリを開くと、設定画面ではなく短いセットアップチャットが始まる。名前 → アクセントカラー → レイアウト（「ベーシック」= シンプルモード / 「エリート」= 詳細モード）→ 接続するアプリ → 入れるプラグイン → ツアー → 最初のタスク、の順にカードで尋ねる。無料の体験モデル `nous/welcome`（OS ユーザーごとに 1 回）で動くため API キーは要らない。コンポーザーの「セットアップをスキップ」で終了でき、設定 > 詳細 > デスクトップと起動の「オンボーディングをもう一度実行」でやり直せる。既存のインストールとリモート接続（SSH・URL・Cloud）では自動では始まらない（リリースノートのみ）。エージェントには `set_theme` ツールが加わり、「紫のダークモードにして」でアプリの配色を変えられる（#137429・#137522・#137807）→ [[09_入門コース/02_インストールと初回起動|インストールと初回起動]]・[[03_設定/08_詳細|詳細]]
- **Nous の無料枠と `/login`**: 他のプロバイダーを設定していない初回のデスクトップ環境には、無料の体験モデルが一度だけ割り当てられる。`/login`（または CLI の `hermes auth upgrade`）で、接続済みのアプリを保ったまま正式な Nous アカウントへ切り替える。請求画面には無料枠の表示（Free tier・`nous/welcome`）と、アプリ内の「Sign in」が加わった（#105258・#105259・#105261）→ [[03_設定/16_請求|請求]]・[[06_リファレンス/05_スラッシュコマンド一覧|スラッシュコマンド一覧]]
- **Connectors（ホスト型アプリとの連携）**: Nous のツールゲートウェイ経由で Linear・Notion などのホスト型アプリをエージェントが操作できる。ブラウザーで一度サインインすると同じターンからツールを使え、Nous アカウントが無くても初回利用時にコネクタ専用の無料 ID が作られる。「スキルとツール」に **Connectors** タブが新設され、ホスト型アプリとローカルの MCP サーバーが 1 つの一覧に並ぶ（MCP タブを置き換え。本文は英語表示）。1 つのアプリに複数の名前付きアカウント（`work` / `home` など）を接続でき、`/connectors` / `hermes connectors` で管理する（#106842・#111008・#135143）→ [[03_設定/12_MCP|MCP]]・[[07_ダッシュボード/02_スキルとツール|スキルとツール]]
- **ローカルモデルのワンクリック導入**: llama.cpp ランタイムを機器に合ったエンジン（CPU / CUDA / Metal / Vulkan / ROCm）で導入・維持し、カタログの各モデルを GPU と RAM で評価して収まる最高品質のビルドを選ぶ。ダウンロードは一時停止・再開でき、エンジンの更新もワンクリック。設定 > プロバイダー > ローカルモデルは、macOS / Windows / Linux（x64・arm64）では `--local` なしで常に表示されるようになった（実機確認）。リリースノートの「Windows, macOS and Linux」はソース上の Linux の条件（x64・arm64 のみ）を省いた書き方（#100667・#111423・#133111）→ [[03_設定/09_プロバイダー|プロバイダー]]
- **安定版リリースと更新チャンネル**: SemVer のテスト済み安定版リリースが出荷されるようになり、ソースインストールは既定で `main` の全コミットではなくリリースからリリースへ移る。設定 > 情報 > バージョンと更新に「アップデートチャンネル」（安定版リリース / すべてのコミット）が加わった。古いリリースへ移る操作はロールバックとして扱われ、必ず確認を挟む（#102765・#135949・#136313）→ [[03_設定/14_情報|情報]]
- **署名付きデスクトップパッケージと統合パッケージマネージャー**: デスクトップアプリは Python と Node を同梱した署名付きパッケージになり、初回起動でのビルドが不要になった。Windows は署名付き MSIX（x64 / ARM64、App Installer または Microsoft Store）、macOS は Apple Silicon 向けの署名・公証済みビルド。下層の新しいパッケージマネージャー `hermes pm` がピン留め・ハッシュ検証したツールと Python 環境を管理し、更新が途中で失敗しても中途半端な状態にならない（リリースノートのみ。#102765・#132361）
- **プラグインカタログ（600 件）**: レビュー済みのコミットにピン留めされたプラグインを、デスクトップと CLI から導入できるカタログが始まり、600 件に増えた。メモリプロバイダー（Honcho・Supermemory・Hindsight・Mem0・OpenViking・Holographic）、Home Assistant、Spotify、Langfuse は本体から各提供元のプラグインへ移った。既存の利用者は更新時か初回起動時にデータを保ったまま自動で移行される（ByteRover と RetainDB は同梱のまま）→ [[03_設定/06_メモリとコンテキスト|メモリとコンテキスト]]・[[07_ダッシュボード/02_スキルとツール|スキルとツール]]
- **パスワードマネージャーでのサイトへのサインイン**: ブラウザーを操作するエージェントが、1Password・Bitwarden・Hermes 自身の暗号化ボールトのログイン情報でサイトへサインインする。パスワードはモデルに渡らない。保存が無いときはマスクされた入力欄で保存を尋ね、ワンタイムコードは会話に出さずに入力し、カード・住所の入力は確認を求める。設定には「パスワードとログイン」画面が新設された（#106480・#107585）→ [[03_設定/20_パスワードとログイン|パスワードとログイン]]
- **Bot Screen**: Linux ゲートウェイで動くボットが専用のデスクトップを持ち、Hermes Desktop がそれをライブで表示する。ログイン・2FA・CAPTCHA で止まったときは画面を引き継いで操作し、終わったら戻す。Docker・SSH・Singularity バックエンドでは、ボットの画面・Computer Use・ブラウザーがサンドボックス内で動く。既定はオフで、ホストに TigerVNC と Xfce が必要（#108914・#121169）→ [[07_ダッシュボード/04_ボット|ボット]]
- **全プロファイルで 1 つのバックエンドと 1 つのゲートウェイ**: プロファイルごとに 1 プロセスではなく、マシンごとに 1 つのメッセージングゲートウェイと 1 つのデスクトップバックエンドが全プロファイルを受け持つ。プロファイルを作るとボットが再起動なしで使え、資格情報・許可リスト・cron ジョブ・セッションはプロファイルごとに分かれたまま。`hermes update` が既存の構成を自動で移行する（#112854・#118246）→ [[07_ダッシュボード/01_プロファイル管理|プロファイル管理]]・[[08_連携/01_連携の全体像|連携の全体像]]
- **サブエージェントのライブ表示と操作**: 実行中のサブエージェントがコンポーザーの上に表示され、各子のタスク・経過時間・ライブの記録と「指示」「停止」ボタンが並ぶ。`/stop` はバックグラウンドの子にも届き、途中までの成果を返す（#105593・#115616）
- **プランを把握するモデルピッカー**: お気に入りのモデル（⇧ クリック）、サブスクリプションの残量と制限のリセット時刻（「残り N% · X にリセット」）、モデル選択と一体の推論強度選択が加わった。`/model X --reasoning high` も使える（#126535・#110346）→ [[03_設定/01_モデル|モデル]]
- **多言語化**: CLI・メッセージングゲートウェイ・TUI・デスクトップの全文字列が 1 つの翻訳カタログを通るようになり、同梱 16 言語で全面対応した（リリースノートの記述。日本語 UI でも英語のまま表示される箇所は各ページに注記）。新しい言語はプラグインとして配布でき（例: `hermes-lang-ko`）、プロファイルごとに個別の文字列を YAML で上書きできる（#126296）
- **軽量化**: 挙動を変えずにコードベースを約 106 万行から約 70 万行（−34%）へ整理した。使用頻度の低い約 19 個のツールは、エージェントが検索したときだけ読み込まれる（`tools.tool_search.defer`）（リリースノートのみ。#102117・#97979）

### デスクトップアプリの改善

- **設定サイドバーが 18 画面 → 19 画面**: 「パスワードとログイン」が Browser の直後に新設された。「アーカイブ済みチャット」は「セッション」に改名され、英語表記だった「Plugins」は「プラグイン」に日本語化された。並びは ツールとキー → セッション →（区切り）プラグイン →（区切り）情報 に変わった。Browser は英語表記のまま → [[06_リファレンス/01_全設定項目索引|全設定項目索引]]
- **設定画面のサブページ化**: 各画面がサイドバーの子項目（サブページ）を持つアコーディオン式になった。選択中の画面だけ子項目が開き、画面を開くと先頭の子項目が表示される。ページ上部にはパンくず（「設定 > 画面 > サブページ」）が出て、画面ごとの大見出しは出なくなった。⌘K の設定内検索は全画面の手作りの設定行とサブページそのものを候補にし、`?setting=<行 ID>` のディープリンクで該当行へスクロール・強調する → [[06_リファレンス/01_全設定項目索引|全設定項目索引]]
- **プラグイン画面の役割変更**: 設定の「プラグイン」は、プラグインの一覧・有効化の画面から、各プラグインの設定ページの入口に変わった。設定を持つプラグインがサイドバーの子項目として並び、エージェントプラグインの設定ページは `config_schema` から自動生成される。一覧・有効化・インストール・アンインストールは「スキルとツール」の新しい **Plugins** タブへ移った（Desktop と Agent を 1 つの表にバッジと 2 列のトグルで並べ、「Git からインストール」とプラグインカタログを備える。実機確認）。同梱のデスクトッププラグインから Accent Picker が外れてサンプル集のリポジトリ（hermes-example-plugins）へ移り、Radio（既定オフ）が加わった → [[03_設定/18_プラグイン|プラグイン]]・[[07_ダッシュボード/02_スキルとツール|スキルとツール]]
- **ツールセットの一覧**: 「スキルとツール」のツールセットから Spotify が外れ（公式プラグインへ移行）、Connections・Kanban・Speech-to-Text が加わった（実機は 24 件）。Computer Use の設定パネルもツールセットにある → [[07_ダッシュボード/02_スキルとツール|スキルとツール]]
- **MCP の移動**: MCP は「スキルとツール」の MCP タブから Connectors タブへ移った。旧 `/settings?tab=mcp` と `/skills?tab=mcp` は `/capabilities?tab=connectors` へ転送される。「スキルとツール」のルートは `/skills` から `/capabilities` に変わり、タブは スキル / ツールセット / Connectors / Plugins の 4 つになった → [[03_設定/12_MCP|MCP]]
- **インターフェースモード（シンプル / 詳細）**: 外観 > ウィンドウとレイアウトに「インターフェースモード」が加わった（既定は詳細）。シンプルはサイドバーとチャットだけの表示で、ターミナル・ファイル・差分のペイン、ステータスバー、ナビのアーティファクトとスケジュール済みジョブを隠す。タイトルバーのレイアウト編集パレット、⌘K、キー割り当て「Toggle Simple mode」からも切り替えられる → [[03_設定/03_外観|外観]]
- **モデル画面**: 4 つのサブページ（メインモデル / 代替モデル / 補助モデル / エージェントの協調）に分かれた。Ultrafast 対応モデルでは速度のセレクト（Standard / Fast / Ultrafast、英語表示）が出る。メイン・代替・補助・MoA のモデル欄で「カスタムモデル…」から ID を手入力できる。補助タスクは 8 件から 12 件になり（音声チャット / トリアージ指定 / カンバン分解 / プロファイル記述を追加）、タスクごとに推論強度（既定は「継承」）を選べる。プラグインが登録した補助タスクも並ぶ。MoA は日本語表示（「エージェント混合（Mixture of Agents）」）になった → [[03_設定/01_モデル|モデル]]
- **外観画面の再編**: 6 つのサブページ（一般 / テーマ / フォントと表示倍率 / ウィンドウとレイアウト / チャット表示 / ペット）に分かれ、行は 18 から 37 に増えた。新しい項目は、モデル料金・起動時に前回のチャットを再開・チャットの文字サイズ・チャットフォント（OpenDyslexic など）・インターフェースモード・アプリ操作（右 / 左）・トレイに最小化・ファイルブラウザ・メッセージの吹き出し・テキストの方向・スレッドのタイムラインバーを非表示・コードの差分を非表示など。内蔵テーマに Classic Hermes が加わって 12 種になった。アプリ内ヒントとガイドツアーは初回利用から 30 日で自動的にオフになる → [[03_設定/03_外観|外観]]
- **パスワードとログイン画面（新設）**: 「保存済みの認証情報」でログイン・支払いカード・住所を追加・削除し、「パスワードマネージャー」で検出した 1Password / Bitwarden の有効化とロック解除を行う。全項目が日本語で表示される → [[03_設定/20_パスワードとログイン|パスワードとログイン]]
- **音声画面**: 3 つのサブページ（音声会話 / 音声認識 / 音声合成）に分かれた。音声会話モード（Voice Chat Mode。`chained` / `gpt-live`）、GPT-Live の声とペルソナ、話しながら文字起こしを表示する Live Transcription、xAI・DeepInfra の STT モデルが加わった（いずれも英語表示）。STT プロバイダーに DeepInfra が加わり 7 種になった。「音声ショートカット」（`voice.record_key`）の入力欄は削除され、録音のショートカットはキーボードショートカットのキー割り当てで設定する（`voice.record_key` は CLI と TUI 専用）→ [[03_設定/07_音声|音声]]
- **詳細画面**: 6 つのサブページ（デスクトップと起動 / エージェントの制限 / ツールへのアクセス / ターミナルのバックエンド / サブエージェント / 出力の制限）に分かれた。「コンピューターをスリープさせない」はオン / オフの 2 択から オフ / 実行中のみ / 常に の 3 択になった（以前オンだった場合は「常に」へ移行）。「Always open links in external browser」（英語表示、既定オフ）と「オンボーディングをもう一度実行」が加わった。セットアップが済んでいない実行バックエンドを選ぶと確認を挟む → [[03_設定/08_詳細|詳細]]
- **安全性画面**: 3 つのサブページ（承認 / プライバシーとネットワーク / チェックポイント）に分かれた。プライバシーとネットワークに「利用統計を収集する」「利用統計を Nous と共有する」が加わった（いずれも既定オフ。共有は収集がオンのときだけ操作できる）→ [[03_設定/05_安全性|安全性]]
- **メモリとコンテキスト画面**: 2 つのサブページ（永続メモリ / コンテキストと圧縮）に分かれ、「Codex 圧縮の自動引き上げ」（既定オン）と「圧縮モデルのタイムアウト（秒）」（既定 120）が加わった。メモリプロバイダーの候補は、同梱の ByteRover / RetainDB とカタログから導入したプロバイダーになった → [[03_設定/06_メモリとコンテキスト|メモリとコンテキスト]]
- **チャット・ワークスペース・Browser 画面**: それぞれ 動作 / 添付ファイル、プロジェクトと検出 / シェル環境 / ファイルと実行、ブラウザープロファイル / ローカル・プライベート URL のサブページに分かれた。項目の増減はない → [[03_設定/02_チャット|チャット]]・[[03_設定/04_ワークスペース|ワークスペース]]・[[03_設定/19_Browser|Browser]]
- **プロバイダー画面**: アカウント / API キー / カスタムエンドポイントに「適用対象」のプロファイル選択が付いた。カスタムエンドポイントに「API Mode」（Auto-detect / Chat Completions / Responses API / Anthropic Messages、英語表示）が加わり、テスト成功時は実際に応答した URL でエンドポイント URL を自動補正する。CLI が管理する外部プロバイダーの行はクリックでターミナルの切断コマンドを実行する。Nous の無料枠は接続済みとして扱わない → [[03_設定/09_プロバイダー|プロバイダー]]

### 破壊的変更・設定キーの変更（移行注記）

> [!caution] 設定ファイルや CLI を併用している場合
> 以下は既定値・設定キー・インストール経路の変更。Desktop の設定 UI だけを使う場合も、古いセッションの自動削除・サンドボックスの既定イメージ・Discord のボット間返信・スキルの整理は挙動が変わる。

- **`sessions.auto_prune` の既定が `false` → `true`**: 90 日間操作の無い終了済みセッションが起動時に自動で削除される。ピン留めしたセッションと開いているセッションは対象外。すべて残したい場合は `sessions.auto_prune: false` にする（設定画面に項目なし）→ [[03_設定/13_アーカイブ済みチャット|セッション]]
- **サンドボックスの既定イメージが `nikolaik/python-nodejs:python3.11-nodejs20` → `nousresearch/hermes-sandbox:desktop`**: `terminal.docker_image` / `modal_image` / `daytona_image`（Singularity は `docker://nousresearch/hermes-sandbox:desktop`）。新しいイメージはボットの画面・Computer Use・ブラウザーをサンドボックス内で動かす表示スタックを含む。保存済みの旧既定値はマイグレーションで破棄され、既存のサンドボックスと明示的に指定したイメージはそのまま残る → [[03_設定/08_詳細|詳細]]
- **`terminal.vercel_runtime` の既定が `node24` → 空欄（非推奨）**: 代わりに `terminal.vercel_image`（`vercel/sandbox/universal:latest`）が加わった
- **スキルのキュレーターの既定**: `curator.stale_after_days` が `30` → `14`、`curator.archive_after_days` が `90` → `30`、`curator.prune_builtins` が `true` → `false`（同梱スキルを刈り込まない）、`curator.backup.keep` が `5` → `2`。旧既定値のままの設定だけが書き換えられ、明示した値は維持される。アーカイブしたスキルは `hermes curator restore` で戻せる
- **`discord.bots_require_inline_mention` の既定が `false` → `true`**: Discord のボットは本文に `@ボット名` を書かないと他のボットに返信しない（返信の通知だけでは反応しない）。人間の発言には影響しない → [[08_連携/03_メッセージング各種|メッセージング各種]]
- **`wake_word.provider` の既定が `openwakeword` → `auto`**: 使えるエンジン（openwakeword / sherpa / porcupine の順）を自動で選ぶ → [[03_設定/07_音声|音声]]
- **`model_catalog.ttl_hours` → `model_catalog.ttl_minutes`（既定 `20` 分）**: モデルカタログのキャッシュ期間のキーが改名された（旧既定は 1 時間）
- **チャットの自動リセットの廃止**: `session_reset` のアイドル / 日次モードが廃止され、新しく始めるのは `/new` か `/reset` だけになった。まだ設定している場合は警告がログに出る（リリースノートのみ）
- **1 マシン 1 ゲートウェイが既定**: `hermes update` は、競合が無ければプロファイルごとのゲートウェイを多重化された既定のゲートウェイへまとめる（`gateway.multiplex_profiles` は既定オンで、`false` を設定しても警告付きで無視される。`gateway.auto_multiplex_migration` は既定オン、`gateway.profile_routes` は既定 空配列、`gateway.multiplex_profile_allowlist` は削除）。一時的に戻す場合は `gateway.standalone: true`（リリースノートのみ）→ [[10_概念解説/01_アーキテクチャ|アーキテクチャ]]
- **メモリプロバイダーなどのカタログ移行**: Honcho・Supermemory・Hindsight・Mem0・OpenViking・Holographic・Home Assistant・Spotify・Langfuse は本体から外れ、カタログのプラグインになった。既存の利用者は自動で移行される。ツールとキーの一覧から Langfuse の 3 行が外れた → [[03_設定/06_メモリとコンテキスト|メモリとコンテキスト]]・[[03_設定/11_ツールとキー|ツールとキー]]
- **同梱スキャナ tirith の廃止**: `security.tirith_enabled` / `tirith_path` / `tirith_timeout` / `tirith_fail_open` は削除され、マイグレーションで保存値も取り除かれる。チェック内容は組み込みの承認ルールに置き換えられた → [[03_設定/05_安全性|安全性]]
- **`cron.model_drift_guard` の削除**: ピン留めしていない cron ジョブは、実行時点のメインモデルを使うようになった（`pinned` で 1 つのモデルに固定）→ [[11_実践レシピ/04_スケジュール自動化|スケジュール自動化]]
- **インストール経路**: マネージドインストールの実行環境は Python 3.14 になった（KittenTTS は 3.14 では使えない）。Windows のデスクトップは MSIX のみで Windows 11 22H2 以降が必要になり、NSIS / MSI のインストーラーは無くなった。macOS アプリの既定ビルドは Apple Silicon のみ（リリースノートのみ）→ [[09_入門コース/02_インストールと初回起動|インストールと初回起動]]
- **プラグイン作者向け**: 旧プラグイン互換のインポート層と `hermes sync`（Skill Sync）が削除された。ツール名の一部が改名された（`todo` → `todo_list`、`cronjob` → `cronjob_manage`、`process` → `process_manage`。旧名も引き続き動く）（リリースノートのみ）
- **スラッシュコマンド**: `/login` が加わり、`/branch`・`/queue`・`/steer`・`/fast` が変わった（下の「スラッシュコマンド」を参照）
- **撤回された機能（本リリースに含まれない）**: Collective Wisdom V1、カード型のスキル / プラグインカタログブラウザー、回答まで待ち続ける承認・確認プロンプト（`approvals.timeout` は引き続き効く）、ボットのグループチャットの並列ラウンド、`hermes cron resnap`、Classic の既定スキン配色、tirith のカタログプラグイン（リリースノートのみ）

### 破壊的変更・設定キーの変更（移行注記）

> [!caution] 設定ファイルや CLI を併用している場合
> 以下は既定値・設定キーの変更。Desktop の設定 UI だけを使う場合も、ターン上限・委譲の並列数・停止時検証・cron の扱いは挙動が変わる。

- **`agent.max_turns` の既定が `500` → `null`（無制限）**: 1 ターンあたりのツール呼び出し上限が既定では効かなくなった（`resolve_turn_limit` が `None` を無制限として扱う）。設定画面（詳細）の「最大エージェントステップ」は空欄が上限なしを意味し、明示した数値はそのまま使われる。上限を保ちたい場合は数値を入れる → [[03_設定/08_詳細|詳細]]
- **`agent.verify_on_stop` の既定が `auto` → `false`**: 停止時の検証は既定で行わない。必要なら明示的に有効にする
- **`delegation.max_iterations` の既定が `50` → `250`、`delegation.max_concurrent_children` が `3` → `10`**: サブエージェントのターン上限と並列数が引き上げられた。設定画面（詳細）の「サブエージェントターン上限」「並列サブエージェント」に反映される → [[03_設定/08_詳細|詳細]]
- **`agent.restart_after_turn_timeout` の既定が `21600` → `1800` 秒、`agent.gateway_turn_lease_timeout` が `1800` → `5`**: 膠着したターンの救済がより早く働く。長時間の単一ターンを意図的に走らせている場合は値を見直す
- **`gateway.scale_to_zero.idle_timeout_minutes` の既定が `5` → `2`**: アイドル時のゲートウェイ縮退が早まった
- **`compression.codex_responses_compact_threshold` の既定が `200000` → `null`**: Codex Responses 経路の圧縮しきい値は自動判定に変わった
- **`tools.tool_search.max_search_limit` の既定が `20` → `25`**: ツール検索の返却上限
- **補助タスク `auxiliary.web_extract.*` の廃止**: `provider` / `model` / `base_url` / `api_key` / `reasoning_effort` / `timeout` の 6 キーが既定値から消え、モデル画面の補助モデルからも「ウェブ抽出」が外れた。代わりに `auxiliary.review.*`（`/review` のレビューサブエージェント）と `auxiliary.background_review.*` が加わった → [[03_設定/01_モデル|モデル]]
- **`stt.provider` の既定値定義の削除**: 既定値 `local` が `DEFAULT_CONFIG` から消え、未設定時は自動検出（ローカル優先）になった。音声画面の「音声認識プロバイダー」自体は残っており、実機では `Local` と表示される。`voice.submit_mode`（`direct`）は `config.yaml` 専用の新キー → [[03_設定/07_音声|音声]]
- **保護された命令ファイルの書き込み承認**: AGENTS.md・スキル・メモリストアへの書き込みは自動承認下でも承認必須になった（#81152）→ [[04_ガイド/03_安全に設定するための確認事項|安全に設定するための確認事項]]
- **ゲートウェイ接続のマシン単位化**: プロファイル別の接続オーバーライド（`connection.json` の `profiles.<profile>.*`）を編集する UI が無くなった。プロファイルは接続先ゲートウェイ側から検出される → [[03_設定/10_ゲートウェイ|ゲートウェイ]]
- **スラッシュコマンドの改名**: `/background` は `/bg` に改名され、旧別名の `/btw` は「会話を中断せずに脇の質問をする」別コマンドとして独立した → [[06_リファレンス/05_スラッシュコマンド一覧|スラッシュコマンド一覧]]
- **撤回された機能（本リリースに含まれない）**: Model Council モード（`/council`）、DCP コンテキストエンジン、WS 専用ゲートウェイサーバー（#94245。#96118 で差し戻し。seq 付きイベント再生 #94219 は出荷）。Electron は 40.10.2 に戻された
- **供給網対応**: 上流の侵害を受けて Blender の MCP カタログエントリと同梱スキルが削除された（#83404）。プラグインのインストールには Tier-1 セキュリティスキャンが入る（#80728）→ [[03_設定/12_MCP|MCP]]

### 破壊的変更・設定キーの変更（移行注記）

> [!caution] 設定ファイルや CLI を併用している場合
> 以下は既定値・設定キー・インストール経路の変更。Desktop の設定 UI だけを使う場合も、ターン上限と STT の言語は挙動が変わる。

- **Node.js 26 が必須**: installers / heal / upgrade のすべての経路で必要になった。管理対象の Node・uv が PATH の裸解決より優先され、旧世代の管理ツリーは対象メジャーへ自動修復される（#76459）
- **Homebrew と pip / PyPI ホイールのインストールチャンネルが廃止**: サポートされるのはシェルインストーラ・Docker・Nix のみになった（#68217）
- **`agent.max_turns` の既定が 90 → 500**: 1 ターンあたりのツール呼び出し（イテレーション）の上限。複雑なタスクが日常的に 90 回を超えていたため引き上げられた。設定画面（詳細）に既存の入力欄があり、明示的に設定済みの値は影響を受けない → [[03_設定/08_詳細|詳細]]
- **`tools.tool_search.threshold_pct` の既定が 10 → 5**: ツール一覧の自動表示に使うコンテキスト長比率のしきい値。予算を縮小するかわりに、縮退時はサーバー要約ヒントで補う
- **`stt.language` の新設と既定 `en`**: STT のグローバル既定言語。誤った言語検出を防ぐために明示指定へ変わった。日本語で音声入力する場合は変更が要る → [[03_設定/07_音声|音声]]
- **`checkpoints.delete_orphans` の廃止**: workdir が消えたチェックポイントを自動削除するトグルが撤去された。workdir の消失が「プロジェクトの削除」なのか「外部ボリューム・ネットワーク共有・VPN が未マウントなだけ」なのかを自動判別できないため。orphan の削除は明示コマンド `hermes checkpoints prune`（`--keep-orphans` でスキップ）に一本化された
- **`display.tool_progress_overrides` の撤去**: 既に非推奨だったキーが既定値から完全に消えた。ユーザーが設定済みの値は後方互換で引き続き読み取られ、`display.platforms` へ畳み込まれる
- **設定マイグレーションの自動対応フロアが v12**: テーブル駆動のマイグレーションレジストリが導入された（#74237・#74200・#74182・#74433）
- **スキルツリーの整理**: `yuanbao`・`segment-anything`・`jupyter`・`heartmula`・`audiocraft` がオプションスキルになり、`claude-marketplace` ソースが削除された。ハブは themes / desktop-plugins / tui-widgets を吸収する形で再編成された（#68595・#70452〜#70456・#73903）→ [[07_ダッシュボード/02_スキルとツール|スキルとツール]]

### 主な新機能

- **初回応答が約 80% 高速化**: コールドスタートの「Initializing agent...」が約 4.3 秒 → 約 0.9 秒に短縮された。CLI・ゲートウェイ・TUI・デスクトップ・cron のすべてに適用され、推論モデルの思考は既定でライブ表示される（`display.show_reasoning` 既定 ON。#59332・#59389）
- **スマート承認が既定に**: フラグされたコマンドを毎回ユーザーに確認する代わりに、補助 LLM が個別に審査して低リスクなら自動承認する `approvals.mode: smart` が既定になった。判定はそのコマンド 1 回限りで、同じパターンに一致する後続コマンドも改めて審査される（#62661）→ [[03_設定/05_安全性|安全性]]
- **ユーザー定義の拒否ルール `approvals.deny`**: fnmatch グロブに一致したターミナルコマンドを無条件でブロックする。yolo モード（承認オフ）でも適用される（#59164）
- **`/deny <理由>`**: 保留中の危険コマンドを理由付きで拒否し、拒否した理由をエージェントに伝えて軌道修正させる（#54518）→ [[06_リファレンス/05_スラッシュコマンド一覧|スラッシュコマンド一覧]]
- **プラグインによる承認ゲートの再導入**: プラグインの `pre_tool_call` フックが `approve` アクションを返すと、そのツール呼び出しが危険コマンドと同じ人間の承認ゲートへエスカレーションされる。エージェント側から承認をスキップする手段はなく、承認の記憶粒度はプラグインが指定するルールキー単位。人が応答できない非対話コンテキストではフェイルクローズする → [[03_設定/05_安全性|安全性]]
- **スラッシュコマンドの追加・変更**: `/compress` に `/compact` 別名と `--preview`、`/sessions search <キーワード>`、`/model --once`（次の 1 ターンだけ上書き）、`/fast` と `/reasoning` の `--global`（付けない限りセッション限定）、`/battery`（CLI のみ・既定オフ）が加わった。導入済みスキルは `/skill-a /skill-b やること` のように先頭へ最大 5 個を並べるスタック起動に対応し（CLI・TUI。オートコンプリートとゴーストテキスト付き）、Telegram・Discord・Matrix では `/reasoning`・`/fast` をネイティブのボタンで選べる → [[06_リファレンス/05_スラッシュコマンド一覧|スラッシュコマンド一覧]]
- **請求（Billing）**: デスクトップの設定に「請求」タブが追加された。CLI・TUI では `/subscription` で Nous プランの確認・変更（アップグレード費用のプレビュー付き）、`/topup` で残高確認と課金管理ができる。旧 `/credits`・`/billing` は `/topup` の Remote Spending 画面に統合された（#51639・#61054・#61067）→ [[03_設定/16_請求|請求]]
- **パスワードマネージャー連携（SecretSource）**: プラガブルな SecretSource インターフェースが追加され、Bitwarden と 1Password（`op://` 参照）からロード時にシークレットを取得できる。複数ボールトの同時有効化、決定的な優先順位、競合警告、変数ごとの由来表示に対応。API キーを平文 `.env` に置かずに済む（#59498）
- **reasoning effort に `max`・`ultra` を追加、モデル別・タスク別・MoA スロット別の制御**: 思考の深さの上位 2 段階が全サーフェスで選べるようになった（スケールが小さいプロバイダーへは自動クランプ）。config でのモデル別上書き、補助モデルのタスク別指定、MoA プリセットのスロット別指定、CLI のセッション限定 `/reasoning`、GLM-5.2 のネイティブ reasoning_effort 制御も加わった（#62650・#64458・#64597・#64631・#67946・#58884）→ [[03_設定/01_モデル|モデル]]
- **MoA の強化**: `reference_max_tokens` で参照モデルの出力を制限してレイテンシを削減できる。プリセット別の fanout 頻度（`user_turn` ならユーザーターンごとに 1 回だけ諮問）、不完全なプリセット保存の API 境界での拒否なども追加（#56756・#57591・#64756）

### 破壊的変更・設定キーの変更（移行注記）

> [!caution] 設定ファイルや CLI を併用している場合
> 以下は既定値・設定キーの変更。Desktop の設定 UI だけを使う場合も、承認まわりと推論表示は挙動が変わる。

- **`approvals.mode` の既定が `manual` → `smart`**: 危険コマンドの承認を補助 LLM が肩代わりする。従来どおり全件を自分で確認するには `approvals.mode: manual` を明示する（2026-07-22 実機確認）→ [[03_設定/05_安全性|安全性]]
- **`approvals.timeout` の既定が 60 秒 → 300 秒**: メッセージング経由の承認は通知に気付くまで時間がかかり、60 秒では失効しやすかったため（2026-07-22 実機確認）
- **`display.show_reasoning` の既定が ON**: 推論モデルの思考がライブ表示される。以前の挙動に戻すには `false` を明示する（2026-07-22 実機確認）
- **`updates.pre_update_backup` の 3 値化**: 真偽値から `quick` / `full` / `off` の 3 値になり、既定は `quick`（軽量スナップショット）。旧設定は `true` → `full`、`false` → `off` として解釈される（2026-07-22 実機確認）
- **ゲートウェイのセッション自動リセットが既定オフ**: 同梱テンプレートが自動リセットを有効にしなくなり、既定は `none`（圧縮以外でコンテキストを自動破棄しない）。必要なら `session_reset` セクションでオプトインする（#60194）
- **kimi-k2.x の整理**: Nous Portal・OpenRouter のカタログが kimi-k2.x から `moonshotai/kimi-k3` に置き換わった（Kimi Coding 直結エンドポイントでは k2 系モデルも引き続き選べる。2026-07-22 実機確認）
- **MoA の temperature 既定送信の廃止**: `reference_temperature` / `aggregator_temperature` は未設定なら API に送らず、プロバイダー既定に任せる（2026-07-22 実機確認）
- **`delegation.max_async_children` の廃止**: 委譲の同時実行上限は `max_concurrent_children` に統合され、旧キーの値は読み込み時に自動で引き継がれる
- **Iteration Budget Pressure の廃止**: イテレーション残量が減った際にモデルへ自動警告する機能が削除された（#59389）
- **`hermes serve` の純ヘッドレス化**: Web UI のビルド・配信を行わないバックエンド専用コマンドになった（#55923）
- **推論レベルの表示ラベルの変更**: v0.18 までは `xhigh` の日本語表示が「最大」だった。現在は `xhigh` が「特高」と表示され、「最大」は新設の `max` を指す。過去のメモや手順書に「最大」とある場合は、どちらのレベルを指しているか確認する（2026-07-22 実機確認）→ [[03_設定/01_モデル|モデル]]
- **メモリプロバイダーの選択肢整理**: ドロップダウンが「内蔵のみ」「Honcho」「Hindsight」の 3 択になり、従来あった「Builtin」の明示選択が無くなった（空欄＝内蔵のみに統合）。保存済みの `builtin` は現在値としてのみリストに残る。内蔵メモリは `memory.provider` ではなく「永続メモリ」（`memory.memory_enabled`）で制御されるため、選び直す必要はない（2026-07-22 実機確認）→ [[03_設定/06_メモリとコンテキスト|メモリとコンテキスト]]
- **`delegation.child_timeout_seconds` の既定変更**: v0.17.0 実機採取時の既定は 600 秒だったが、現行の既定は `0`（タイムアウトなし）で、子エージェントは API エラー・ツールエラー・反復上限だけで停止する（変更されたバージョンは未特定。2026-07-22 実機確認）→ [[03_設定/08_詳細|詳細]]
- **MCP ツール名の命名規約の統一**: MCP 由来のツール名が `mcp__<サーバー名>__<ツール名>` 形式に統一された（Claude Code・Codex と共通の規約。英数字とアンダースコア以外は `_` に置換）。`tools.include` / `tools.exclude` には引き続きサーバー固有の素のツール名を書く → [[03_設定/12_MCP|MCP]]

### プラットフォーム別の変更

> [!note] 接続設定そのものは変わらない
> 以下はゲートウェイ経由で接続する各プラットフォーム側の挙動・`config.yaml` の変更で、Desktop の連携設定パネルの項目は変わらない。接続手順は [[08_連携/03_メッセージング各種|メッセージング各種]] を参照。

- **Slack**: 応答生成中のステータス行が「考え中」の固定文ではなく、実行中のツールに合わせてライブ更新される。実行中のコマンドや読み取り中のファイル名が表示され、ツール実行の合間は従来の表示に戻る（#67080）
- **Discord ─ 取りこぼしメッセージの回復**: 再接続やゲートウェイ再起動の間に届いていたメッセージを、復帰時にさかのぼって処理できる（#66149）。`discord.missed_message_backfill.*` で制御する（`enabled` 既定 `false`。有効時は既定で直近 6 時間・スキャン上限 100 件・再配信上限 10 件）。対象チャンネルは `channels` で指定し、空なら `allowed_channels`（許可チャンネル）と `free_response_channels` の和集合を走査する（`config.yaml` のコメントは「空なら `free_response_channels`」とあるが、実際の既定挙動は両者の和集合）
- **Discord ─ 自動作成スレッドのリネーム**: メンションから自動作成されたスレッドの名前が、最初のターンの後に LLM が生成したセッションタイトルへ自動リネームされる（#60187）。作成直後はメッセージ冒頭から作った仮の名前が付く
- **Discord ─ インタラクティブビューのタイムアウト設定**: 実行承認・確認・選択肢などのボタン付きビューの有効時間を `approvals.discord_prompt_timeout` で設定できる（#60230）。既定 300 秒で、30〜900 秒にクランプされる（Discord のインタラクショントークンが約 15 分で失効するため）
- **Discord ─ 実行承認プロンプトでのオーナーメンション**: `discord.approval_mentions`（既定 `false`）を有効にすると、実行承認プロンプトで数値 ID の許可ユーザーをメンションする（#60493）。共有チャンネル・スレッドで承認依頼を見落としにくくなる
- **Discord ─ 承認ボタンの管理者限定ゲート**: ゲートウェイ設定の Discord `extra` ブロックで `require_admin_for_exec_approval: true`（既定 `false`）にすると、危険コマンドの承認・拒否ボタンを押せるユーザーを `allow_admin_from` に列挙した管理者だけに制限できる（#51751）。既定では許可ユーザーの誰でも押せるため、複数人が参加する共有サーバーでは有効化が安全側の選択になる。管理者を 1 人も列挙せずに有効化した場合は誰も押せない側に倒れる（フェイルクローズ）
- **Google Chat**: clarify（選択肢を尋ねるプロンプト）が Google Chat のカードとして表示される（#65546）
- **Telegram**: フォーラムグループのトピック単位で自由応答（メンションなしで応答）を許可できる（#65543）。`config.yaml` の `telegram.free_response_topics` に `<チャット ID>:<スレッド ID>` 形式で列挙する（環境変数 `TELEGRAM_FREE_RESPONSE_TOPICS` でも指定可）。チャット全体を開放する `free_response_chats` と違い、特定のトピックだけを開放できる
- **WhatsApp ─ clarify がネイティブ投票に**: 選択肢を尋ねる clarify プロンプトが WhatsApp ネイティブの投票（Baileys ポール）としてレンダリングされ、投票結果がそのまま回答として扱われる（#58865）
- **WhatsApp ─ 位置情報と受信メタデータ**: ネイティブの位置ピンの送信に対応し、引用返信・添付の種別（音声・ステッカー・連絡先など）・リアクション・投票・位置情報といった受信メタデータの取り込みが強化された（#58865）
- **WhatsApp ─ ダッシュボードからのペアリング**: Web ダッシュボードのチャネル画面に WhatsApp のペアリングフローが追加された（#60571）。QR コードの表示から、スマートフォンの WhatsApp「リンク済みデバイス」でのスキャン、ログイン状態の確認までをダッシュボード上で完結できる

- **メモリプロバイダーの OAuth 接続**: OAuth 対応の外部メモリプロバイダーへ、API キーを貼らずにブラウザーサインインで接続できる → [[03_設定/06_メモリとコンテキスト|メモリとコンテキスト]]
- **「今すぐ更新」ボタン**: 準備済み更新を情報画面からその場でインストールできる → [[03_設定/14_情報|情報]]
- **Computer Use の権限パネル**: スキル画面に、macOS の TCC 許可（アクセシビリティ・画面収録）などを確認・付与するパネルが追加（英語表示）
- **ペットの改善**: 散歩（roam）の挙動が穏やかで現実的になり、Alt+ホイールでサイズ変更、ポップアウトオーバーレイの通知対応など。孵化（`/hatch`）の演出改善と、CPU 負荷を抑えたクロマ処理も加わった → [[03_設定/03_外観|外観]]
- **バックアップ**: Web UI からのバックアップ作成・インポート・ダウンロード。更新前スナップショットに `projects.db` とかんばんボードを含む

### 破壊的変更・設定キーの変更（移行注記）

> [!caution] 設定ファイルや CLI を併用している場合
> 以下は Desktop の設定画面には現れない、config・エージェントレイヤの変更。設定ファイル・`.env`・CLI を直接編集している場合は確認が必要。

- **google-gemini-cli / google-antigravity OAuth プロバイダーの削除**: Gemini の OAuth 経路が整理された。Gemini は Google AI Studio の API キー、または新設の Google Vertex AI プロバイダーを使う。デスクトップでは「アカウント」から Google Gemini (OAuth + Code Assist) カードが消えて接続候補が 10 件 → 9 件になり、「API キー」からも「Gemini」カード（主キー `HERMES_GEMINI_CLIENT_SECRET`、詳細項目 `HERMES_GEMINI_CLIENT_ID` / `HERMES_GEMINI_PROJECT_ID`）がカタログごと削除された（2026-07-02 実機画面で確認。候補数は v0.19.0 で Fireworks AI の固定行が加わる前の時点）→ [[03_設定/09_プロバイダー|プロバイダー]]
- **verify-on-stop の既定値調整**: 一度だけ実行される v32 マイグレーションで既定値が調整される。実機の製品既定は `agent.verify_on_stop: auto`（サーフェスに応じた自動判定。2026-07-02 実機確認）。ドキュメントだけの編集ではスキップされ、メッセージングサーフェスでは無効
- **圧縮の in-place 化が既定に**: コンテキスト圧縮で新しいセッション ID を切らず、同一セッション ID のまま圧縮する `in_place` が既定 True になった
- **cron ジョブ保存のプロファイル単位への差し戻し**: v0.17 で導入されたグローバル保存が取り消され、プロファイル単位に戻った
- **`auth.json` のクローン廃止**: プロファイル複製時に OAuth グラントを複製すると相互失効を招くため、複製しない挙動へ変更
- **`prompt_caching.enabled` トグルの差し戻し**: 再評価のため一旦取り下げ

### v0.17.0 リリース後の main で追加された機能

> [!note] 対象
> 正式リリースは v0.17.0 のままだが、`main` はローリング更新され、リリース（2026-06-19）後も機能が加わっている。以下は 2026-07-01 時点で `main`（参照コミット `7eb9716`）に入り、実機で確認した主な追加分。これらはその後 v0.18.0 の正式リリースに含まれた。

- **ペット（Petdex マスコット）**: 設定 → 外観にアニメーションマスコットを追加。CLI・TUI・デスクトップに表示され、ツール実行・成功・失敗など Hermes の状態に反応する。既定オフ、装飾のみでトークン・キャッシュ・挙動に影響しない。`/pet`・`/hatch` コマンド、`hermes pets` CLI、Cmd+K パレット、Shift+クリックのポップアウトオーバーレイを備える → [[03_設定/03_外観|外観]]
- **Mixture of Agents（MoA）**: 複数モデルの視点を集約する仮想モデルプロバイダー。設定 → モデルでプリセットを作成・編集し、モデルドロップダウンの `MoA presets` から選ぶ。`/moa` は既定プリセットでの単発実行 → [[03_設定/01_モデル|モデル]]
- **新しいスラッシュコマンド**: `/goal`・`/subgoal`（常設ゴール／Ralph ループ）、`/steer`（割り込みなしの誘導）、`/queue`、`/branch`、`/background`、`/learn`、`/blueprint`、`/curator`、`/kanban`、`/snapshot`、`/debug` など多数 → [[06_リファレンス/05_スラッシュコマンド一覧|スラッシュコマンド一覧]]

### 破壊的変更・設定キーの変更（移行注記）

> [!caution] 設定ファイルや CLI を併用している場合
> 以下は Desktop の設定画面には現れない、config・エージェントレイヤの変更。Desktop の設定 UI だけを使う場合は影響しないが、設定ファイル・`.env`・CLI を直接編集している場合は移行が必要。

- **`write_mode`（3値）→ `write_approval`（真偽値）**: ファイル書き込み承認の設定キーが、3値の `write_mode` から真偽値 `write_approval` に置き換わった。Desktop 側のファイル承認は設定画面の承認モード（[[03_設定/05_安全性|安全性]] の `approvals.mode`: manual / smart / off）で別管理されており、こちらは変更されていない。
- **エージェント用 `send_message` ツールの削除**: エージェントが呼び出せる `send_message` ツールが廃止された。Desktop の通常チャットには影響しない。
- **`tool_progress_grouping`（新規・設定可能化）**: ツール進捗表示のグルーピングを設定できるようになった。
- **`curator.consolidate`（既定 off）**: メモリ curator のスキル統合はオプトイン（既定 off）。プルーニングは従来どおり既定 on。既定では追加トークンを消費しない（[[03_設定/06_メモリとコンテキスト|メモリとコンテキスト]]）。
- **プロバイダー環境変数の移動**: `CLAUDE_CODE_OAUTH_TOKEN` が Anthropic カードの別名キーへ移り、`HERMES_QWEN_BASE_URL` は旧 DashScope カードの詳細欄から外れて非カード変数になった。`ALIBABA_CODING_PLAN_*` / `KILOCODE_API_KEY` / `NOVITA_*` はそれぞれ専用カードへ移った（[[03_設定/09_プロバイダー|プロバイダー]]）。

これらのうち Desktop の設定 UI 定義（`constants.ts`）に露出しないキーは、本ガイドの各設定ページには記載していない（ソース確認済み）。
